13. OpenClaw Applications ​

NOTE

The robot comes pre-configured with OpenClaw and related packages from the factory. Initial operation on Jetson Orin series versions does not require copying or compiling these packages. If errors or incompatibilities occur while running applications according to the tutorial, refer to 13.1 Preparation to re-import the provided backup resource files, packages, and skills into their corresponding directories, and compile them. After successful compilation, proceed with the application tutorials.

13.1 Preparation ​

13.1.1 Deploying Resources and Building the Environment on the Controller ​

Before running a ClawPi OpenClaw application, copy the robot-side OpenClaw resources to the designated directory on the controller and build the required packages.

1. Drag openclaw_resource.zip from the Robot folder in the OpenClaw resources to the desktop, and then extract it.

2. Install MobaXterm . Refer to the Remote Access and File Transfer Tutorial, and use MobaXterm to drag the extracted openclaw_resource folder to the following directory on the ClawPi controller:

bash
/home/pi/docker/tmp/

3. Open the VNC remote desktop, and click the terminal icon on the desktop to open a terminal.

4. Run the following command to copy the resources to the container home directory:

bash
cp -r ~/shared/openclaw_resource ~/

5. Run the following command to enter the resource folder:

bash
cd openclaw_resource

6. Run the deployment script:

bash
zsh deploy.sh package

7. At each subsequent prompt, enter y and press Enter.

8. Run the following command to enter the workspace and build the openclaw_controller package:

bash
cd ~/ros2_ws/ && colcon build --event-handlers console_direct+ --cmake-args -DCMAKE_BUILD_TYPE=Release --symlink-install --packages-select openclaw_controller

9. When the build is complete, run the following command to reload the environment:

bash
source ~/.zshrc

13.1.2 Setting Up the Virtual Machine Development Environment ​

  • Installing VMware

Virtual machine software allows another operating system to run within the current operating system. This section uses VMware Workstation as an example. The installation steps are as follows:

1. Extract the virtual machine software package from Resources/1 Virtual Machine Software.

2. Open the extracted folder and double-click the installer with the .exe extension.

3. Complete the installation in the sequence shown below.

4. When VMware starts for the first time, enter the product key and click Continue.

  • Starting the Local VMware Services

    1. Return to the host computer and press Win+R to open the Run dialog box. Enter control, and then press Enter to open Control Panel.

2. Click Administrative Tools, and then double-click Services.

3. Locate the VMware services shown below.

4. Right-click each VMware service, and then click Start.

  • Importing the Virtual Machine Image

    1. In VMware, click Open a Virtual Machine.

2. Locate and open the virtual machine file in Resources/2 Virtual Machine Image.

3. Select a storage location, click Import, and wait for the import to finish.

4. After the import is complete, the virtual machine is ready to use.

  • Configuring the Virtual Machine

    1. Select the imported virtual machine, and then click Edit virtual machine settings.

2. Click Network Adapter, and then select Bridged mode.

3. Click Display, and then clear the Accelerate 3D graphics check box.

NOTE

The first startup may take longer than usual. This is normal. Bridged networking is recommended so that the virtual machine and ClawPi are on the same LAN.

13.1.3 Configuring OpenClaw ​

On the Virtual Machine

1. If OpenClaw is already installed, run the following command to display its version and verify that the OpenClaw CLI is available:

bash
openclaw --version

Importing Files into the Virtual Machine

1. Drag openclaw_resource.zip from the OpenClaw resource folder to the desktop.

2. Click the folder icon on the desktop to open the default home directory.

3. Drag openclaw_resource.zip into the virtual machine.

4. Click the terminal icon on the desktop to open a new terminal.

5. Run the following command to extract openclaw_resource.zip to the current home directory:

bash
unzip openclaw_resource.zip

6. Run the following command to enter the resource folder:

bash
cd openclaw_resource

7. Run the script:

bash
zsh deploy_pi.sh

8. At each subsequent prompt, enter y and press Enter.

9. The existing IDENTITY.md, MEMORY.md, and skills items are backed up to an automatically created backup directory.

10\. Grant execute permission to the image-capture script:

```bash
chmod +x ~/.openclaw/workspace/skills/ros2-cam-subscribe/scripts/cam_subscribe.sh
```

11\. Run the following command to reload the environment:

```bash
source ~/.bashrc
```

13.2 Obtaining and Configuring an LLM API Key ​

NOTE

This section requires registering on the official OpenAI website and obtaining an API key for accessing large language models.

13.2.1 OpenAI Account Registration and Deployment ​

  1. Copy and open the following URL: https://platform.openai.com/docs/overview, then click the Sign Up button in the upper-right corner.
  1. Register and log in using a Google, Microsoft, or Apple account, as prompted.
  1. After logging in, click the Settings button, then go to Billing, and click Payment Methods to add a payment method. The payment is used to purchase tokens.
  1. After completing the preparation steps, click API Keys and create a new key. Follow the prompts to fill in the required information, then save the key for later use.
  1. The creation and deployment of the large model have been completed, and this API will be used in the following sections.

13.2.2 API Configuration ​

  1. Use NoMachine to connect to the robot, then click the terminal icon on the left side of the interface to open a terminal.
  1. Enter the following command to configure OpenClaw.
bash
openclaw config
  1. Select Local (this machine) and press Enter.
  1. The model item needs to be configured here. Select Model and press Enter.
  1. Select OpenAI, press Enter.

  1. Select OpenAI API key and press Enter.

  2. Paste the previously generated API key here.

  1. Select openai/gpt-5.4 or another suitable model, then press Enter.

  2. This completes the model configuration.

13.3 Configuring Telegram ​

NOTE

Telegram can be set up from either the app or Telegram Web. The steps below use Telegram Web.

Telegram Web address: https://web.telegram.org/k/

  • Step 1: Log in to Telegram.

Scan the QR code with the app, or log in with a phone number and verification code.

  • Step 2: Search for BotFather.

Search for BotFather in the search bar at the upper-left corner of Telegram, then open the officially verified account with the blue checkmark.

  • Step 3: Create a bot and get the token.

Send /newbot in the chat to create a Bot and get the Token. The bot username must end with _bot.

NOTE

A Token will be generated after the setup is complete. Save it securely and do not share it. This token will be required later in the OpenClaw configuration.

  • Connect Telegram to OpenClaw through the Plugin

After the Telegram bot is ready, configure OpenClaw from the server or local terminal.

  • Step 1: Enable the Telegram plugin in the OpenClaw config.
bash
openclaw config set channels.telegram.enabled true
  • Step 2: Add the Telegram bot Token to OpenClaw.
powershell
openclaw config set channels.telegram.botToken "TELEGRAM_BOT_TOKEN"
  • Step 3: Start the OpenClaw Gateway service.
bash
openclaw gateway
  • Step 4: In the BotFather chat, click the bot link shown in the message, such as t.me/openclaw_hiwonder_bot, to open the bot chat. Then click START.

NOTE

openclaw gateway must be started before clicking START in Telegram. Otherwise, the pairing code will not be received.

  • Step 5: During the first chat, the Telegram Bot sends a pairing code. Run the following command on the server to complete pairing.
  • Step 6: Open a new command-line terminal and run the following command. Replace <code> with the Pairing code received in Telegram. Do not include the angle brackets when entering it.
bash
openclaw pairing approve telegram <code>
  • Step 7: After the command runs successfully, send a test message to the Telegram Bot, such as hello. If the bot replies like an AI assistant, the Telegram connection to OpenClaw is working properly.

The Telegram integration for OpenClaw is now complete.

13.4 Smart Logistics Handling ​

Smart Logistics Handling is the core application in the ClawPi OpenClaw course. In response to a researcher's natural-language instruction, the robot travels to a specified area, searches for an industrial component of the requested color, and delivers it to the designated drop-off area. If the requested color is not found, the robot reports the inventory in the current area and asks what to do next.

13.4.1 Preparation ​

  • Complete 13.1 Preparation.

  • Complete 13.2 Obtaining and Configuring an LLM API Key.

  • To use Telegram, complete 13.3 Configuring Telegram.

  • Set up the smart logistics map as shown below.

13.4.2 Procedure ​

NOTE

  • The robot must be connected to a network. Set it to LAN Mode. If Direct Connection Mode is used, connect an Ethernet cable.

  • The virtual machine and ClawPi must be on the same subnet.

  • Areas A, B, and C, the start area, and the drop-off area on the map must match the program configuration.

  • Before starting, tune and verify the color thresholds, line-following parameters, and pick position.

(1) On the Robot

1. Open the VNC remote desktop, and stop the app autostart service in the ClawPi terminal:

bash
~/.stop_ros.sh

2. Start the Smart Logistics OpenClaw application:

bash
ros2 launch example smart_logistics.launch.py

3. To enable local text-to-speech, or TTS, output, run the following command if supported by the installed package:

bash
ros2 launch example smart_logistics.launch.py use_tts:=true

4. To use the configured LLM to generate TTS text or spoken content, run the following command with the model key configured in this course:

bash
ros2 launch example smart_logistics.launch.py use_tts:=true use_large_models_tts:=true

(2) On the Virtual Machine

1. Open a terminal and start the OpenClaw Gateway:

bash
openclaw gateway run

2. Open a new terminal and start the OpenClaw TUI:

bash
openclaw tui

3. Enter the following task in the TUI or Telegram chat window:

text
Go to the workstation in Area C and pick up the red industrial component.

4. Wait for ClawPi to complete line following, recognition, picking, and placement.

5. If the robot reports that the requested color is not available in the specified area, enter:

text
Go to Area B, look around, and take a photo.

6. If the requested color is still not found in Area B, enter:

text
Go to Area C and look around.

7. After locating the red component, the robot picks it up and delivers it to the designated drop-off area.

(3) Stopping the Application

1. Press Ctrl+C in each active robot-side terminal to stop the processes.

2. If the ROS 2 nodes do not exit normally, open a new terminal and run:

bash
~/.stop_ros.sh

3. Press Ctrl+C in the virtual-machine terminals running the OpenClaw Gateway and TUI.

13.4.3 Expected Result ​

After the application starts, natural-language instructions can be used to direct ClawPi through the following smart logistics tasks:

  • Travel to Area A, B, or C as instructed.

  • Identify the colors of the industrial components in the current area.

  • Report the available inventory if the requested color is not found.

  • Switch to another target area in response to a follow-up instruction.

  • Pick up the requested component and deliver it to the designated drop-off area.

  • Retain previously observed inventory information and prioritize known areas in later tasks.

13.4.4 Step-by-Step Testing ​

If OpenClaw does not execute a task sent through the TUI or Telegram, use the following tests to isolate the issue.

13.4.4.1 Querying the Current Location ​

bash
ros2 service call /smart_logistics/get_location std_srvs/srv/Trigger "{}"

13.4.4.2 Sending a Destination ​

Travel from the start area to Area A:

bash
ros2 service call /smart_logistics/execute interfaces/srv/SetString "{data: 'A'}"

Travel to Area B:

bash
ros2 service call /smart_logistics/execute interfaces/srv/SetString "{data: 'B'}"

Travel to Area C:

bash
ros2 service call /smart_logistics/execute interfaces/srv/SetString "{data: 'C'}"

NOTE

If the drop-off areas are named 1, 2, 3 or P1, P2, P3 in the source code, set the data field to match the source configuration.

13.4.4.3 Turning Around and Traveling to the Next Area ​

If the robot is not in the start area and must turn around or change routes, use the package interface to send the next destination. For example:

bash
ros2 service call /smart_logistics/execute interfaces/srv/SetString "{data: 'B'}"

13.4.4.4 Testing Pick Operations ​

Pick up a red component:

bash
ros2 service call /smart_logistics/pick interfaces/srv/SetString "{data: 'red'}"

Pick up a green component:

bash
ros2 service call /smart_logistics/pick interfaces/srv/SetString "{data: 'green'}"

Pick up a blue component:

bash
ros2 service call /smart_logistics/pick interfaces/srv/SetString "{data: 'blue'}"

13.4.4.5 Testing Placement ​

bash
ros2 service call /smart_logistics/place std_srvs/srv/Trigger "{}"

13.5 Troubleshooting ​

Q1: colcon build fails.

Possible causes: A dependency is missing, the code contains a syntax error, or a path is configured incorrectly.

Solutions:

1. Review the build error and identify the package that failed. To repeat the deployment and build procedure, see 13.1.1 Deploying Resources and Building the Environment on the Controller.

2. Verify that all dependencies have been installed correctly with rosdep install.

3. Check the configuration in CMakeLists.txt and package.xml.

Q2: OpenClaw reports an error at startup.

Possible causes: The resources have not been deployed, the package has not been built, or an environment variable is not set.

Solutions:

1. Verify that the resources were deployed as described in 13.1 Preparation.

2. Run colcon build to rebuild the package.

3. Verify that MACHINE_TYPE and other required environment variables are set correctly.

Q3: Bridged networking cannot be configured.

Possible causes: The network configuration file is invalid, or the bridge interface is disabled.

Solutions:

1. Check the syntax of the network configuration file.

2. Verify that the bridge interface has been created and enabled. For bridged-network settings, see 13.1.2 Setting Up the Virtual Machine Development Environment.

3. Restart the network service to apply the configuration.

Q4: The Telegram app cannot be configured.

Possible causes: The App ID or App Secret is incorrect, or the callback URL is misconfigured.

Solutions:

1. Retrieve the App ID and App Secret again from the Telegram Open Platform. For credential retrieval, see 13.3.1 Obtaining the Telegram App Credentials.

2. Verify that the callback URL is correct and reachable.

3. Check that all required app permissions have been granted.

Q5: The robotic arm does not respond.

Possible causes: A servo cable is loose, the control node is not running, or a servo ID is configured incorrectly.

Solutions:

1. Check that the robotic-arm servo cables are securely connected.

2. Verify that the servo control node is running.

3. Verify that the configured servo IDs match the installed hardware.
