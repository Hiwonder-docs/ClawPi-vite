5. LCD Display Course ​

5.1 LCD Display Overview ​

ClawPi features a 1.9-inch LCD that displays robot status information, the live camera feed, and voice interaction content.

5.1.1 Specifications ​

ItemSpecification
Display size1.9 inches
Resolution170 × 320 pixels
Display typeDot-matrix LCD, square screen
ColorFull color, RGB
Communication interfaceDedicated communication cable

5.1.2 Functions ​

The LCD serves the following functions on ClawPi:

  • Status Information: Shows the robot's current status, battery level, and other information.

  • Camera Feed: Shows the live camera feed.

  • Function Menu: Shows the function-selection interface.

  • Voice Interaction: Shows spoken input and responses from the AI assistant.

  • Startup Screen: Shows the startup animation when the robot boots.

5.1.3 Software Architecture ​

The LCD software uses a client-server architecture:

  • LCD Display Service: Runs in the background and controls the content shown on the LCD.

  • ROS 2 Nodes and Standalone Python Scripts: Connect to the LCD display service over a socket to send display commands.

  • Communication Protocol: Uses JSON-formatted messages for communication.

5.2 Displaying an Image ​

5.2.1 Operating Principle ​

The standalone send_lcd_image.py script displays a local image on the LCD. It reads the image file and sends the data directly to the LCD display service over a socket. No ROS 2 image topic or image-forwarding node is required.

The workflow is as follows:

1. Read the Image File: The script reads the image bytes from the path provided on the command line.

2. Encode the Image in Base64: The image bytes are converted to a Base64 string for inclusion in a JSON command.

3. Connect to the LCD Display Service: The script connects to the local LCD display service at 127.0.0.1:8765, reads the service greeting, and then sends the command.

4. Take Control of the LCD: The script sends a camera screen payload and takes control of the current LCD output to display the selected image.

5. Restore the Default Screen: The script continues running to keep the image on the LCD. Pressing Ctrl+C sends a clear command and restores the controller's default screen.

The script reads the raw bytes of the specified image file and sends them to the LCD display service. Two image fit modes are available: cover fills the entire screen and may crop the image, while contain displays the complete image and may leave blank margins.

5.2.2 Starting and Stopping Image Display ​

NOTE

Commands are case-sensitive. Press Tab to autocomplete commands and paths.

1. Power on the robot and use VNC Viewer to connect to the Raspberry Pi desktop. For connection instructions, see 2. Installing Remote Desktop Tools and Accessing the Docker Container / 2.1 Installing and Connecting the Remote Desktop Tool.

2. Click the terminal icon shown above on the desktop to open a terminal.

3. Make sure the current terminal is inside the Docker container and that the LCD display service is running. This example sends the image directly to the service.

4. Prepare a test image. A test image is provided at /home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png. Alternatively, upload another image to the robot and use its actual path in the commands below.

5. Run the following command to display the image. The script uses cover mode by default, scaling the image and cropping it when necessary to fill the LCD.

bash
python3 /home/ubuntu/ros2_ws/src/lcd_display_pkg/scripts/send_lcd_image.py /home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png

Command Syntax:

text
python3 script_path image_path [fit_mode]

  • python3: Runs the script with Python 3.

  • Script Path: Specifies the fixed location of the LCD image display script: /home/ubuntu/ros2_ws/src/lcd_display_pkg/scripts/send_lcd_image.py.

  • Image Path: Specifies the image file to display and is required. This example uses /home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png. If the path is incorrect, the terminal displays image file not found.

  • [fit_mode]: Specifies the optional image fit mode. The square brackets indicate that this argument can be omitted. If omitted, the mode defaults to cover. Enter contain to display the complete image. Place the fit mode after the image path.

To display a different image, replace only the image path. For example:

bash
python3 /home/ubuntu/ros2_ws/src/lcd_display_pkg/scripts/send_lcd_image.py /home/ubuntu/my_photo.png

6. To display the complete image without cropping, add contain after the image path. If the image and LCD have different aspect ratios, blank margins remain around the image.

bash
python3 /home/ubuntu/ros2_ws/src/lcd_display_pkg/scripts/send_lcd_image.py /home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png contain

7. The terminal remains active while the image is displayed. When finished, press Ctrl+C in that terminal. The script releases control of the LCD and restores the default screen.

NOTE

Use Ctrl+C to exit cleanly so that the script can restore the LCD during cleanup.

5.2.3 Expected Result ​

After the command runs, the script sends the image to the LCD display service. Once the service confirms the request, the selected image appears on the LCD and the terminal shows output similar to the following:

text
displaying: /home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png (cover)
Press Ctrl+C to restore the default LCD screen.

displaying indicates that the image was sent successfully and has taken control of the LCD. The value shown after the image path identifies the active fit mode. The command in Step 6 shows contain instead of cover. cover fills the LCD, while contain keeps the entire image visible.

The script continues running while the image is displayed. Pressing Ctrl+C prints a restoration message in the terminal and sends a clear command to the LCD display service:

text
restoring LCD screen...
LCD screen restored.

LCD screen restored. confirms that the LCD display service has released manual image control and returned to the controller's default screen.

Common errors and solutions are listed below:

  • Incorrect Image Path: The terminal displays send_lcd_image.py: error: image file not found: image_path. Confirm that the image exists and use its full path.

  • Empty or Unreadable Image File: The terminal displays a message beginning with send failed:, such as send failed: image file is empty. Check the file contents and read permissions.

  • LCD Display Service Unavailable: The terminal displays a connection error beginning with send failed:. Confirm that the current terminal is inside the Docker container and that the LCD display service is running at 127.0.0.1:8765.

  • Display Request Rejected: The terminal displays LCD error: .... Use the returned message to check the status of the LCD display service.

  • Restoration Failed: If LCD restore error: or LCD restore failed: appears after Ctrl+C is pressed, manual image control was not cleared successfully. Restore the LCD display service, run the image display script again, and exit with Ctrl+C.

5.2.4 Program Analysis ​

The source file used in this section is located in the Docker container at /home/ubuntu/ros2_ws/src/lcd_display_pkg/scripts/send_lcd_image.py.

The program flow is shown below:

text
Local image file -> Read image bytes -> Base64 encoding -> JSON command -> Socket transmission -> LCD display service -> LCD

The script uses argparse to accept two command-line arguments: a required image path and an optional fit mode. After parsing the arguments, it expands ~ in the path and verifies that the path points to a file. If validation fails, argparse prints an error and terminates the program.

python
parser.add_argument("image_path", type=Path, help="path to the image")
parser.add_argument(
    "fit_mode",
    nargs="?",
    type=fit_mode,
    default="cover",
    help="cover: fill screen; contain: show full image",
)

  • image_path:Specifies the local image file to display. The example uses the absolute path/home/ubuntu/ros2_ws/src/lcd_display_pkg/resource/images/test_image.png, so the command does not depend on the terminal's current directory. To display another image, replace this path with the image's actual path. The script calls expanduser() to expand ~ and uses is_file() to verify that the file exists.

  • fit_mode: Specifies the optional display mode. The script removes leading and trailing spaces and converts the value to lowercase. cover is the default and fills the screen, cropping the image when necessary. contain keeps the entire image visible and may leave blank margins. The script also accepts the common misspelling contrain and treats it as contain. Any other value produces the message fit_mode must be cover or contain.

  • Image File Validation

Before sending the image, send_image reads the raw image bytes and rejects an empty file:

python
image_bytes = image_path.read_bytes()
if not image_bytes:
    raise ValueError("image file is empty")

If the path is invalid, argument validation fails. If the file exists but is empty, the script displays send failed: image file is empty when it attempts to send the image.

  • Reading and Sending the Image

The send_image function reads the image bytes, encodes them, and adds them to the JSON payload sent to the LCD display service:

python
image_bytes = image_path.read_bytes()
payload = {
    "screen": "camera",
    "title": "",
    "image_base64": base64.b64encode(image_bytes).decode("ascii"),
    "fit_mode": mode,
    "flip_horizontal": False,
    "save_preview": False,
    "camera_owner": "manual_image",
    "interrupt_emotion": True,
    "camera_takeover": True,
}

image_base64 contains the Base64-encoded image. fit_mode controls how the image fits the LCD. flip_horizontal is set to False, so the image is not mirrored horizontally. camera_takeover and interrupt_emotion allow the manually selected image to take over the current LCD output.

  • Socket Communication and Response Handling

The send_command function connects to the LCD display service at 127.0.0.1:8765. It reads the service's welcome message, sends one line of JSON data, and reads the JSON response:

python
with socket.create_connection((LCD_HOST, LCD_PORT), timeout=2.0) as connection:
    with connection.makefile("rwb") as stream:
        stream.readline()
        stream.write((json.dumps(payload, separators=(",", ":")) + "\n").encode("utf-8"))
        stream.flush()
        response = stream.readline()

The script parses the response as JSON and checks the ok field returned by the LCD display service. If the connection or image read fails, the response is invalid JSON, or the service returns no data, the script prints send failed: and exits. If ok is not true, it prints LCD error: and exits. After a successful response, the script sets image_active to True, prints the display message, and continues running.

  • Keeping the Image Active and Restoring the Default Screen

After the image is sent successfully, the script remains active in a sleep loop so that control of the LCD is not released immediately. When Ctrl+C is pressed, or the process receives a termination signal such as SIGTERM, SIGHUP, or SIGQUIT, the signal handler converts the event to KeyboardInterrupt and enters the cleanup routine:

python
def clear_lcd() -> dict:
    return send_command({"command": "clear"})

The program calls clear_lcd() in the finally block only when the image has successfully taken control of the LCD and image_active is True. The function sends {"command": "clear"} to release manual image control and restore the controller's default screen. If the service reports a failure or an exception occurs during cleanup, the terminal displays the corresponding restoration error.

5.3 Displaying Video ​

5.3.1 Operating Principle ​

The image_to_lcd ROS 2 node handles live video display on the LCD. The camera continuously publishes a ROS 2 image topic, and the node forwards the latest frame to the LCD display service as follows:

1. Subscribe to the Camera Image Topic: By default, the node subscribes to /image_raw. For raw Image messages, it converts the image with CvBridge. For CompressedImage messages, or topics ending in /compressed, it uses the compressed image data directly.

2. Convert and Encode the Image: A raw image can be resized according to output_width and output_height, then encoded as JPEG at the specified jpeg_quality. Compressed images are not encoded again.

3. Retain Only the Latest Frame: The image callback stores the latest JPEG frame without sending it over the network. A new frame replaces any older frame that has not yet been sent, preventing the LCD from displaying an increasingly delayed video feed.

4. Send at the Configured Frame Rate: A separate sending thread limits the transmission rate according to fps, with a default maximum of 60 frames per second. Before sending, it checks the current transfer state and topic-generation counter to prevent an obsolete frame from appearing after transmission stops or the topic changes.

5. Display the Frame on the LCD: The node encodes the JPEG data in Base64 and sends it, together with settings such as fit_mode and flip_horizontal, to the LCD display service through DisplaySocketClient. The service renders the frame on the LCD.

The LCD therefore displays the latest available camera frame instead of playing a backlog of frames in sequence. If the camera frame rate exceeds the configured transmission rate, the node prioritizes low latency.

5.3.4 Program Analysis ​

The source file used in this section is located in the Docker container at /home/ubuntu/ros2_ws/src/lcd_display_pkg/lcd_display_pkg/image_to_lcd.py.

In Section 5.2, send_lcd_image.py sends a static image directly to the LCD display service. In this section, the image_to_lcd node processes the camera feed. The following analysis explains how the node converts a continuously published raw image stream into frames for the LCD.

text
Camera -> /image_raw (Image) -> _on_raw callback -> Latest JPEG frame -> _send_loop -> LCD display service -> LCD
  • Initializing the Node and Subscribing to the Camera Topic

By default, the node sets both topic and preview_topic to /image_raw and subscribes to camera images using the sensor-data QoS profile. set_image_topic creates the subscription. If the node is already subscribed to another topic, it destroys the old subscription before switching to the new topic.

python
self.declare_parameter("topic", "/image_raw")
self.declare_parameter("preview_topic", "/image_raw")
self.declare_parameter("image_type", "raw")
self.declare_parameter("fps", 60.0)
self.declare_parameter("jpeg_quality", 80)
self.declare_parameter("stale_timeout", 5.0)

self.image_qos = qos_profile_sensor_data
self.set_image_topic(topic)

qos_profile_sensor_data is designed for low-latency sensor-data transmission. fps sets the maximum LCD transmission rate, jpeg_quality sets the JPEG encoding quality for raw images, and stale_timeout specifies how long the node can go without receiving a new camera frame before timeout protection is triggered.

  • Converting Raw Images and Retaining the Latest Frame

When the camera publishes raw Image messages, the _on_raw callback first checks whether the node is running. If it is, the callback converts the message to an OpenCV BGR image. If both output width and height are configured, the node resizes the image before encoding it as JPEG. After encoding succeeds, the callback updates only the latest frame and frame sequence number in memory. It does not wait for network transmission.

python
if not self.running:
    return
self.last_image_at = time.monotonic()
try:
    import cv2
    cv_img = self.cv_bridge.imgmsg_to_cv2(msg, desired_encoding="bgr8")
    if (
        self.output_width > 0
        and self.output_height > 0
        and (cv_img.shape[1], cv_img.shape[0])
           != (self.output_width, self.output_height)
    ):
        cv_img = cv2.resize(
            cv_img,
            (self.output_width, self.output_height),
            interpolation=cv2.INTER_AREA,
        )
    params = [
        int(cv2.IMWRITE_JPEG_QUALITY),
        max(1, min(100, self.jpeg_quality)),
    ]
    ok, buf = cv2.imencode(".jpg", cv_img, params)
    if ok:
        with self.frame_ready:
            if not self.running:
                return
            self.latest_jpeg = buf.tobytes()
            self.latest_jpeg_seq += 1
            self.frame_ready.notify()
        with self.stats_lock:
            self.stats_received += 1
except Exception as e:
    self.get_logger().warn(f"JPEG encode failed: {e}")

last_image_at is used for image-timeout checks, while stats_received is used to calculate the average input frame rate shown in the log. A JPEG encoding error produces a warning but does not stop the node. This design allows the camera callback to return quickly. If the camera frame rate is high or the LCD display service briefly slows down, a newer frame replaces any older unsent frame, preventing the video from falling progressively behind.

  • Sending Thread and Frame-Rate Limit

_send_loop waits for new frames in a separate thread. The thread sends a frame only when an unsent frame is available and the next permitted send time has been reached.

python
if jpeg_bytes is None or jpeg_seq == self.sent_jpeg_seq:
    self.frame_ready.wait(timeout=0.5)
    continue

now = time.monotonic()
if now < next_send_at:
    self.frame_ready.wait(timeout=next_send_at - now)
    continue

self.sent_jpeg_seq = jpeg_seq
transfer_generation = self.transfer_generation
next_send_at = now + self.min_interval

min_interval is calculated from fps. At the default 60 frames per second, transmissions are at least 16.7 ms apart. transfer_generation increments whenever transmission stops or the topic changes. The value is checked again before sending to prevent a frame from the previous topic or transfer session from appearing after a switch.

  • Building the LCD Payload

With the output and frame locks held, the sending function checks running and the transfer-generation value again. If the current frame is still valid, it encodes the latest JPEG in Base64 and constructs the camera screen payload required by the LCD display service. A normal camera frame is mirrored according to flip_horizontal. Algorithm-result images from topics beginning with /image_result have already been processed by the result-image publisher, so the node does not mirror them again.

python
flip_horizontal = self.flip_horizontal and not topic.startswith("/image_result")
payload = {
    "screen": "camera",
    "title": "",
    "image_base64": base64.b64encode(jpeg_bytes).decode("ascii"),
    "fit_mode": self.fit_mode,
    "flip_horizontal": flip_horizontal,
    "save_preview": False,
}
if preview_mode:
    payload["camera_owner"] = "key2_preview"
if interrupt_emotion:
    payload["interrupt_emotion"] = True
resp = self.client.send(payload)

The first frame sent at startup or after a topic change includes interrupt_emotion, which interrupts the current emotion display and switches the LCD to the camera feed. Only after the LCD display service returns ok does the node count the frame as successfully sent and include it in the average transmission-time statistics. A connection failure or service error produces a warning in the log.

  • Timeout Handling and Stopping Transmission

The node checks for an image timeout every 0.5 seconds. If no camera frame is received for longer than stale_timeout, it calls stop_transfer to stop forwarding images. Because /image_raw is the preview topic in this example, the last frame remains on the LCD when transmission stops. In preview mode, the heartbeat is renewed automatically. For a non-preview function-result topic, a heartbeat or image timeout stops transmission and either returns to the function menu or clears the LCD, depending on the function-menu configuration.

5.4 Displaying Emotions ​

5.4.1 Operating Principle ​

The emotion_to_lcd ROS 2 node displays emotions on the LCD. It subscribes to /lcd_display/emotion, parses emotion commands received as std_msgs/msg/String messages, and sends them over a socket to the local LCD display service.

The workflow is shown below:

text
Terminal publishes emotion message -> /lcd_display/emotion -> emotion_to_lcd node -> LCD display service -> LCD

Emotion messages can be sent in three formats:

1. Emotion Name: For example, happy.

2. Emotion ID: For example, 1. The LCD display service maps the ID to the corresponding emotion resource.

3. JSON Configuration: A JSON object can specify the emotion, display duration, fit mode, and scale in a single message.

By default, the node connects to the LCD display service at 127.0.0.1:8765, uses contain as the fit mode, and sets the emotion scale to 0.85. After receiving a valid emotion message, the node marks the display as active and refreshes the heartbeat timer. If the heartbeat is not refreshed before the timeout expires, the node stops displaying the emotion.

NOTE

Commands are case-sensitive. Press Tab to autocomplete commands and paths.

2. Click the terminal icon shown above on the desktop to open a terminal. Run the following command and press Enter to stop the app service that starts automatically at boot:

bash
~/.stop_ros.sh

3. Run the following command and press Enter to start the emotion display node. Keep this terminal open so that the node can continue receiving emotion messages:

bash
ros2 launch lcd_display_pkg emotion_to_lcd.launch.py

4. Open a second terminal using the icon shown above. Run the following command and press Enter to display the happy emotion. --once publishes one message, /lcd_display/emotion is the emotion-control topic, and std_msgs/msg/String is the message type.

bash
ros2 topic pub --once /lcd_display/emotion std_msgs/msg/String "{data: 'happy'}"

5. An emotion can also be specified by numeric ID. The following command sends ID 1:

bash
ros2 topic pub --once /lcd_display/emotion std_msgs/msg/String "{data: '1'}"

6. To customize the display settings, pass a JSON object in the data string. The following example uses the emotion name thinking, requests a three-second display duration, selects contain mode, and sets the emotion scale to 1.0.

bash
ros2 topic pub --once /lcd_display/emotion std_msgs/msg/String \
  "{data: '{\"emotion\":\"thinking\",\"duration_seconds\":3,\"fit_mode\":\"contain\",\"emotion_scale\":1.0}'}"

NOTE

Keep the backslashes (\) that escape the double quotation marks in the inner JSON object. Without them, the shell removes the quotation marks and the node cannot parse the parameters in data as JSON.

JSON Parameters:

  • emotion: Specifies the emotion name or ID to display.

  • duration_seconds: Specifies the requested display duration in seconds. The value 3 requests a three-second display.

  • fit_mode: Specifies how the emotion image fits the LCD. contain keeps the complete image visible, while cover fills the display area.

  • emotion_scale: Sets the emotion scale factor. A value of 1.0 uses the normal scale. The default is 0.85.

7. The default heartbeat timeout is five seconds. After a single emotion message is sent, the node stops the display if it receives no new emotion message for approximately five seconds. To display an emotion for longer than five seconds, modify the command in Step 3. For example, to display an emotion for eight seconds, set the heartbeat timeout to more than eight seconds:

bash
ros2 launch lcd_display_pkg emotion_to_lcd.launch.py heartbeat_timeout:=10.0

When using the default launch command, set duration_seconds to no more than five seconds. Alternatively, publish another emotion message within five seconds to refresh the heartbeat.

8. When finished, press Ctrl+C in the first terminal to stop the node. During shutdown, the node sends stop_emotion to the LCD display service to end the current emotion display. If return-to-menu behavior is enabled, the LCD returns to the function menu.

5.4.3 Expected Result ​

After the node starts, the terminal displays configuration information similar to the following:

text
[INFO] [emotion_to_lcd]: emotion_to_lcd: /lcd_display/emotion -> 127.0.0.1:8765, loops=1, duration=0.0s, fit=contain, scale=0.85, heartbeat=5.0s, text_topic=/lcd_display/emotion_text

After happy is sent, the LCD switches to the happy emotion. After 1 is sent, it displays the emotion resource assigned to ID 1. After the JSON configuration example is sent, the LCD displays the thinking emotion using contain mode and a scale factor of 1.0.

The command containing --once exits immediately after publishing one message. This is normal. emotion_to_lcd.py does not print a success message when the LCD display service processes an emotion successfully. Therefore, an immediate return to the prompt and no new output in the node terminal do not indicate a failure. Confirm success by checking whether the emotion changes on the LCD.

When the LCD display service processes an emotion command successfully, the node marks the emotion display as active and refreshes the heartbeat. If the connection fails, the node terminal displays LCD service connection failed. If the LCD display service returns an error, it displays LCD service error: .... If the message format or a parameter is invalid, the node displays ignored emotion message: ... and does not send the message to the LCD display service.

With the default configuration, a single emotion message refreshes the heartbeat for five seconds. If no new message arrives before the heartbeat expires, the node displays heartbeat timeout, stopping emotion_to_lcd display and sends stop_emotion. For a longer display duration, set heartbeat_timeout to a value greater than the required duration when starting the node, or publish another emotion message before the timeout.

5.4.4 Program Analysis ​

The source file used in this section is located in the Docker container at /home/ubuntu/ros2_ws/src/lcd_display_pkg/lcd_display_pkg/emotion_to_lcd.py.

The program flow is shown below:

text
String emotion message -> parse_emotion_payload -> DisplaySocketClient -> LCD display service -> Emotion shown on LCD
  • Parameters and Topic Subscriptions

During initialization, the node declares the emotion topic, LCD display service address, default display settings, and heartbeat timeout, then subscribes to /lcd_display/emotion:

python
self.declare_parameter("topic", "/lcd_display/emotion")
self.declare_parameter("host", "127.0.0.1")
self.declare_parameter("port", 8765)
self.declare_parameter("heartbeat_timeout", 5.0)
self.declare_parameter("default_loop_count", 1)
self.declare_parameter("default_duration_seconds", 0.0)
self.declare_parameter("default_fit_mode", "contain")
self.declare_parameter("default_emotion_scale", 0.85)

self.create_subscription(String, self.topic, self.on_emotion, 10)

  • topic: Specifies the topic used to receive emotion commands. Defaults to /lcd_display/emotion.

  • host, port: Specify the host and port of the LCD display service. The default endpoint is 127.0.0.1:8765.

  • default_loop_count: Sets the number of playback loops used when the message does not provide a value. Defaults to 1.

  • default_duration_seconds: Sets the display duration used when the message does not provide a value. Defaults to 0.0.

  • default_fit_mode: Sets the default image fit mode. Defaults to contain.

  • default_emotion_scale: Sets the default emotion scale. Defaults to 0.85.

The node also subscribes to /lcd_display/emotion_text and text topics associated with speech recognition and TTS so that it can overlay conversation text on the emotion display. This example publishes emotion messages only to /lcd_display/emotion.

  • Parsing and Sending Emotion Messages

The on_emotion callback receives a String message and uses parse_emotion_payload to parse an emotion name, numeric ID, or JSON string into a dictionary payload for the LCD display service:

python
payload = parse_emotion_payload(
    message.data,
    self.default_loop_count,
    self.default_duration_seconds,
    self.default_fit_mode,
    self.default_emotion_scale,
)
response = self.client.send(payload)

If parsing fails, the program catches ValueError, logs a warning, and does not send the invalid command. After sending, the node checks the LCD display service response. A connection failure produces None. If ok is not true, the node logs a service error. The current emotion-display state is updated only after a successful response. The success branch updates display_active and refreshes the heartbeat without printing a separate success message.

duration_seconds, fit_mode, and emotion_scale are passed to the LCD display service in the payload generated by parse_emotion_payload. emotion_to_lcd.py does not create a separate stop timer for duration_seconds. Node-side stop protection is controlled by heartbeat_timeout. The actual display duration therefore depends on both the LCD display service and the node's heartbeat timeout.

  • Stop Commands, Heartbeat Handling, and Shutdown Cleanup

The node recognizes stop, stop_emotion, clear, and clear_emotion as stop commands. After one of these commands is processed successfully by the LCD display service, the node cancels any pending text-overlay cleanup and marks the emotion display as inactive.

python
is_stop_command = command in {"stop", "stop_emotion", "clear", "clear_emotion"}
if is_stop_command:
    self._cancel_pending_tts_clear(clear_active=True)
    self._mark_inactive()
else:
    self.display_active = True
    self._refresh_heartbeat()

When display_active is true and the heartbeat expires, _on_heartbeat_timeout calls _stop_emotion_display. This function sends {"command": "stop_emotion"} to the LCD display service. If return-to-menu behavior is enabled, it stops the emotion and then displays the function menu. When the node exits, destroy_node also stops the emotion and closes the socket client:

python
def destroy_node(self) -> bool:
    self._cancel_pending_tts_clear(clear_active=True)
    self._stop_emotion_display()
    self.client.close()
    return super().destroy_node()

To shut down cleanly, press Ctrl+C in the terminal that started the node. This allows the program to send the stop command and release the connection.

5.5 Troubleshooting ​

Q1: The LCD Does Not Turn On

Possible causes: The display cable is loose, the LCD display service is not running, or the display hardware has failed.

Solutions:

1. Make sure the LCD cable is connected securely.

2. Make sure the robot is powered on, and wait for startup to complete. For startup instructions, see 1. ClawPi User Manual / 1.3.4 Powering On.

3. Restart the robot and check whether the startup logo appears.

Q2: An Image Does Not Appear

Possible causes: The image path is incorrect, the LCD display service is not running, or the image format is unsupported.

Solutions:

1. Verify that the image path is correct and the file exists. For the complete image-display procedure, see 5.2.2 Starting and Stopping Image Display.

2. Make sure the LCD display service is running on port 8765.

3. Use a PNG or JPEG image.

Q3: The LCD Display Service Is Not Running

Possible causes: The LCD display service did not start, or its port is in use.

Solutions:

1. Restart the robot. The LCD display service starts automatically during boot.

2. Check whether another program is using port 8765.

3. Start the LCD display service manually.

Q4: The Image File Cannot Be Found

Possible causes: The path is misspelled, the file does not exist, or the current account lacks sufficient permissions.

Solutions:

1. Use ls to confirm that the file exists at the specified path. For image-path preparation and command usage, see 5.2.2 Starting and Stopping Image Display.

2. Check the path for spaces or special characters. Quote the path if necessary.

3. Use an absolute path, such as /home/ubuntu/test.png.

Q5: The LCD Displays Corrupted Content

Possible causes: The transmitted data is incorrectly formatted, or the LCD display service is malfunctioning.

Solutions:

1. Clear the LCD and send the content again using the clear command.

2. Restart the LCD display service.

3. Check that the JSON payload is formatted correctly.
