10. Machine Learning Course ​

10.1 Introduction to Machine Learning ​

  • Introduction

Artificial intelligence, or AI, is a field concerned with theories, methods, technologies, and systems that simulate, extend, or augment human intelligence.

AI encompasses areas such as machine learning, computer vision, natural language processing, and deep learning. Machine learning is a subfield of AI, while deep learning is a class of machine-learning methods.

Since its emergence, AI has continued to mature in both theory and technology, its range of applications has steadily expanded, and it has gradually developed into an independent field.

  • What Is Machine Learning?

Machine learning is a core component of AI and a fundamental approach to giving machines intelligent capabilities. It is an interdisciplinary field that draws on probability, statistics, approximation theory, convex analysis, algorithmic complexity, and other disciplines.

Machine learning studies how computers can simulate or implement human learning behavior to acquire new knowledge or skills, reorganize existing knowledge structures, and continually improve performance. In practice, data is used to train a model, and the trained model is then used to make predictions.

AlphaGo, for example, was the first AI system to defeat a professional Go player and later a world champion. Its main operating principle is deep learning, which extracts information by learning the internal patterns and hierarchical representations of sample data.

  • Types of Machine Learning

Machine learning is commonly divided into supervised and unsupervised learning. The main distinction is whether the training data includes known labels or target outcomes.

(1) Supervised Learning

In supervised learning, an algorithm learns from examples paired with known answers or labels. It is one of the most common machine-learning approaches.

Labeled Data: Supervised training data normally contains input features and corresponding labels or outputs. Input features describe the data, while the label is the target variable that the model is expected to predict or classify. For example, a large collection of dog images can be labeled dog. This label serves as the known answer, allowing the model to learn to identify dogs in new images.

Model Selection: In supervised learning, a suitable model is selected to represent relationships in the data. Common models include linear regression, logistic regression, decision trees, support vector machines, or SVMs, and deep neural networks. The appropriate model depends on the data characteristics and the nature of the problem.

Feature Engineering: Feature engineering preprocesses and transforms raw data to extract useful features. Typical operations include data cleaning, handling missing values, normalization or standardization, feature selection, and feature transformation. Effective feature engineering can improve model performance and generalization.

Training and Optimization: Labeled training data is used to fit the relationships in the data. The training process normally defines a loss function, selects an appropriate optimization algorithm, and iteratively adjusts model parameters to minimize the loss. Common optimization methods include gradient descent and stochastic gradient descent.

Model Evaluation: After training, evaluate the model to determine its performance on new data. Common metrics include accuracy, precision, recall, F1 score, and the receiver operating characteristic curve, or ROC curve. The evaluation results help determine whether the model is suitable for practical use.

In summary, supervised learning uses labeled training data to train a model, then uses that model to predict or classify new, unlabeled data. The main stages are selecting an appropriate model, performing feature engineering, training and optimizing the model, and evaluating its performance. Together, these stages form the basic workflow of supervised learning.

(2) Unsupervised Learning

In unsupervised learning, the algorithm receives data without predefined labels and attempts to discover underlying structures or relationships.

For example, when a dataset contains many unlabeled images of cats and dogs, the method groups the images into two categories, one containing cat images and the other containing dog images.

10.2 Machine-Learning Frameworks ​

  • Common Machine-Learning Frameworks

Common machine-learning frameworks include PyTorch, TensorFlow, PaddlePaddle, and MXNet.

(1) PyTorch

Torch is an open-source machine-learning framework distributed under a BSD-style license. It supports intensive multidimensional array operations and is widely used in machine learning. PyTorch is a machine-learning framework based on Torch. Compared with Torch, PyTorch is more flexible, supports dynamic computation graphs, and provides a Python interface.

Unlike TensorFlow's static computation graph, PyTorch uses a dynamic computation graph that can change in real time as required by the computation. It also supports GPU-accelerated tensor computation, dynamic graph construction, and automatic gradient calculation.

(2) TensorFlow

TensorFlow is an open-source machine-learning framework that can quickly build neural networks and support network training, evaluation, and saving. It provides a straightforward way to implement machine-learning and deep-learning concepts. It combines computational algebra with optimization techniques, making many mathematical expressions easier to compute.

TensorFlow can run on machines of different types and sizes, from supercomputers to embedded systems and other computers in between. It can use a CPU, a GPU, or both. Compared with many other machine-learning frameworks, TensorFlow is particularly well suited to industrial deployment and production environments.

(3) PaddlePaddle

PaddlePaddle is a deep-learning framework developed by Baidu. Built on years of Baidu's deep-learning research and production experience, it integrates a core training and inference framework, foundational model libraries, end-to-end development toolkits, and a wide range of supporting components. It is China's first independently developed, feature-rich, open industrial-grade deep-learning platform.

In recent years, deep learning has shown strong performance across many machine-learning fields. It is widely applied to image recognition, speech recognition, natural language processing, robotics, online advertising, automated medical diagnosis, finance, and other areas.

(4) MXNet

MXNet is a deep-learning framework with interfaces for languages including Python, C++, Scala, and R. It provides dataflow graphs similar to Theano and TensorFlow, strong support for multi-GPU configurations, and higher-level model-building blocks similar to Lasagne and Blocks. It can run on a wide range of hardware, including mobile phones.

MXNet is designed for efficiency and flexibility. Accelerated libraries such as MXNet provide tools that help developers use GPU and cloud-computing resources effectively. MXNet can be distributed across dynamic cloud architectures through a distributed parameter server and can achieve near-linear scaling across multiple GPUs and CPUs.

10.3 YOLO26 Overview, Architecture, and Workflow ​

10.3.1 Introduction to the YOLO Family ​

(1) The YOLO Family

YOLO, short for You Only Look Once, is a family of single-stage, deep-learning-based regression methods for object detection.

Before YOLOv1, two-stage R-CNN detectors dominated object detection. They could provide high accuracy, but their multi-stage pipelines were often too slow for real-time applications.

YOLO reframes object detection as a regression problem. The complete image is used as the network input, and the output layer directly predicts bounding-box locations and classes. Compared with traditional object-detection methods, YOLO provides fast detection and high average accuracy.

(2) YOLO26

YOLO26 builds on earlier YOLO models and is optimized to significantly improve both detection speed and accuracy.

An object-detection algorithm can generally be divided into four modules: the input, backbone, neck, and detection head. The following points describe the YOLO26 improvements by module:

1. Input: During model training, YOLO26 uses Mosaic data augmentation to improve training speed and network accuracy. It also uses adaptive anchor-box calculation and adaptive image scaling.

2. Backbone: YOLO26 introduces Focus and CSP structures.

3. Neck: As with YOLOv4, YOLO26 uses an FPN + PAN structure in this part, although the implementation details differ.

4. Detection Head: YOLO26 uses the same anchor-box mechanism as YOLOv4 in the output layer. Its main changes are the use of GIoU loss and DIoU-NMS for filtering predicted boxes.

10.3.2 YOLO26 Model Architecture ​

(1) Basic Components

1. Convolutional Layer: Extracting Image Features

Convolution can be understood as the effect that repeated occurrences of the same action at earlier points in time have on an object's current state. In this explanation, convolution is divided into two parts, "reversal" and "accumulation."

"Reversal" refers to flipping the data, while "accumulation" refers to accumulating the influence of earlier data on the current data. Flipping the data establishes the relationships needed as a reference when calculating the accumulated influence.

YOLO26 processes images, which are two-dimensional in computer vision, so the convolution used here is also two-dimensional. The purpose of 2D convolution is to extract image features. Before applying 2D convolution, first understand the convolution kernel.

A convolution kernel is the unit region used for each convolution calculation. Its region is measured in pixels, and the pixels within each region are accumulated during the calculation. Convolution is generally performed by sliding the kernel across the image, and the kernel size must be configured in advance.

During convolution, the image border may be left unchanged or expanded by a selected number of pixels according to the required effect. The convolution result is then written back to the corresponding positions in the output image. For example, a 6 × 6 image can first be expanded to 7 × 7, processed with the convolution kernel, and then written into a blank 6 × 6 output image.

2. Pooling Layer: Amplifying Image Features

A pooling layer, also called a downsampling layer, is generally used together with a convolutional layer. After convolution, pooling performs further sampling on the features. Common forms include global pooling, average pooling, and max pooling, and each form produces a different effect.

Max pooling is used here as an example. Before applying it, define a filter region, similar to a convolution kernel. During calculation, the filter slides across the feature map and selects pixels within each region.

Max pooling can be understood as retaining the most salient features and removing the remaining features. For example, applying a 2 × 2 filter to a 6 × 6 image produces a new, smaller image.

3. Upsampling Layer: Restoring Image Size

Upsampling can be understood as the reverse of pooling in terms of image size. Pooling makes the image smaller, while upsampling increases it back toward the original size. Only the size is restored, and the pooled features change accordingly.

For example, applying a 3 × 3 filter during upsampling to a 6 × 6 image produces the new image shown below.

4. Batch-Normalization Layer: Organizing Data

Batch normalization can be understood as reorganizing data into a more regular form. Its practical purpose is to reduce computational difficulty and allow the data to map more effectively into the activation function.

Batch normalization reduces feature loss after each calculation so that more features are retained for the next calculation. After repeated calculations, the model can become more sensitive to the data.

5. ReLU Layer: Activation Function

Activation functions are added to introduce nonlinearity into the model. Without an activation function, each layer is effectively a matrix multiplication, and every layer output remains a linear function of the previous input. Regardless of the number of layers, the final output is still a linear combination of the input, which limits the model's ability to adapt to complex situations.

Common activation functions include ReLU, tanh, and sigmoid. ReLU, short for Rectified Linear Unit, is a piecewise function that replaces values below 0 with 0 while leaving positive values unchanged.

6. Add Layer: Tensor Addition

Features can be divided into salient and less-salient features. The Add layer adds feature tensors together to strengthen the salient features.

7. Concat Layer: Tensor Concatenation

The Concat layer concatenates feature tensors, combining features extracted in different ways so that more feature information is retained.

(2) Composite Components

If a model is built only from the basic layers described above, the code can become lengthy, the structure can become confusing, and the hierarchy can be difficult to follow. Grouping these basic components into reusable units makes them easier to call and improves the efficiency of model development.

  1. Convolutional Unit

A convolutional unit consists of a convolutional layer, batch normalization, and an activation function, applied in that order.

  1. Focus Spatial-to-Channel Unit

The Focus operation first divides the input image into multiple larger regions. The small image elements at the same relative position within each region are then concatenated, which splits the original input into several separate images. Finally, a convolutional unit performs the initial sampling on these images.

In the example below, a 6 × 6 image is divided into nine 2 × 2 regions, and each region contains four pixel positions.

The values at position 1 within each region are concatenated to form a 3 × 3 image. Repeating the same process for the other positions splits the original 6 × 6 image into four 3 × 3 images.

  1. Residual Unit

A residual unit helps the model learn small changes in an image. Its structure is relatively simple and works by combining data obtained through two separate paths.

The first path applies two convolutional units to sample the image. The second path does not apply convolutional sampling and instead passes the original image directly. Finally, the data from the first path is added to the data from the second path.

  1. Composite Convolutional Unit

In YOLO26, the composite convolutional unit can be customized by adjusting its convolutional units as needed. It combines data from two processing paths.

The first path contains one convolutional layer. The second path contains 2x + 1 convolutional units and one convolutional layer. After the two paths are concatenated, batch normalization organizes the data, an activation function is applied, and a final convolutional unit performs the last sampling step.

  1. Composite Residual Convolutional Unit

The composite residual convolutional unit replaces the 2x convolutional units in the composite convolutional unit with x residual units. In YOLO26, the residual units can be customized as needed.

  1. Composite Pooling Unit

The output of the convolutional unit is sent to three max-pooling layers while one additional path remains unchanged. The data from all four paths is then concatenated and passed through a convolutional unit. Using the composite pooling unit makes the original features more prominent.

10.3.3 YOLO26 Workflow ​

This section explains the YOLO26 workflow using prior boxes, predicted boxes, and anchor boxes.

  • Prior Boxes

Before an image is fed into the model, target-recognition regions need to be provided. Prior boxes are used to mark these target-recognition regions in advance.

  • Predicted Boxes

Predicted boxes are model outputs and do not need to be set manually. When the first batch of training data is fed into the model, predicted boxes are generated automatically. Positions where objects of the same class appear more frequently are used as predicted-box center points.

  • Anchor Boxes

After a predicted box is generated, its size and position may contain errors. Anchor boxes are used to correct the size and position of the predicted box.

The anchor-box position is determined by the predicted box. To influence where the next predicted box is generated, the anchor box is placed near the relative center of the current predicted box.

  • Training Flow

After logarithmic calibration is completed, prior boxes appear on the image. When the image data is fed into the model, the model generates predicted boxes based on the positions of the prior boxes. Anchor boxes are then generated, and the weights from the current training iteration are updated in the model.

Each newly generated predicted box is affected by the anchor box generated in the previous iteration. As the process repeats, the size and position errors of the predicted boxes gradually decrease until the predicted boxes overlap the prior boxes.

10.4 Training a YOLO26 Model ​

10.4.1 Image Collection and Annotation ​

Training a YOLO26 model requires a large amount of labeled data, so collect and annotate the dataset before starting model training.

Before starting, prepare the images to be collected. This example uses a traffic sign as the target object.

  • Image Collection

    1. Start the robot and connect to it through VNC Viewer.

    2. Click the terminal icon on the desktop to open a terminal.

    3. Enter the following command to stop the app service that starts automatically at boot.

    bash
    ~/.stop_ros.sh

    4. Enter the following command to start the depth-camera service.

    bash
    ros2 launch peripherals depth_camera.launch.py

    5. Open a new terminal, enter the following command, and press Enter to create a directory for the dataset.

    bash
    mkdir -p ~/my_data

    6. Enter the following command to start the image-collection tool.

    bash
    cd ~/software/collect_picture && python3 main.py

save number shows the ID assigned to the next saved image, while existing shows the number of images already saved.

7. Click Select Folder and set the save location to the my_data directory created above.

8. After selecting the directory, click Choose.

9. Place the target within the camera field of view. Click Save (Space) or press the Spacebar to save the current frame.

After clicking Save (Space) or pressing the Spacebar, the tool automatically creates the JPEGImages folder under /home/ubuntu/my_data.

NOTE

Capture the target from different distances, rotations, and viewing angles to improve dataset diversity and model reliability.

10. After collecting the images, click Exit to close the tool.

11. Press Ctrl+C in every terminal opened for this procedure. Image collection is now complete.

  • Image Annotation

After image collection, the images must be annotated. Annotation is essential for preparing a usable dataset because it tells the training model which class the important regions of each image belong to. This allows the model to recognize the same classes later in new images that it has not seen before.

10.4.2 Data-Format Conversion ​

  • Preparation

Before continuing, complete image collection and annotation. For the detailed procedure, see 10.4.1 Image Collection and Annotation.

Before training, define the image classes and convert the annotation data into the format expected by the training program.

  • Format Conversion

Complete image collection and annotation before performing this procedure.

NOTE

Commands are case-sensitive. Press Tab to complete filenames or command keywords.

1. Open a new terminal and enter the following command. If the file does not exist, the editor creates it.

bash
gedit ~/my_data/classes.names

2. Enter the annotated class name left in the file. Put each additional class on a separate line.

NOTE

Each class name must exactly match the name used in labelImg.

3. Press Ctrl+S to save the file, then close the editor.

4. Return to the terminal, enter the following conversion command, and press Enter.

bash
python3 ~/software/xml2yolo.py --data ~/my_data --yaml ~/my_data/data.yaml

NOTE

Set the paths to ~/software/xml2yolo.py and my_data according to their actual locations.

The command uses the following three path arguments:

  • xml2yolo.py: Converts the annotated label format into the label format required for YOLO26 model training. Set the path to match the actual location of the script.

  • my_data: Specifies the annotated dataset directory. Set the path to match the actual dataset location.

  • data.yaml: Specifies the dataset configuration generated after format conversion. In this example, the file is saved in the my_data directory.

  • The generated data.yaml file is shown below.

In data.yaml, the entries under names define the label types, and nc specifies the number of label classes. train identifies the training set, which contains the data used for model training, and the following value specifies its path. val identifies the validation set, which is used to validate results during training, and its following value also specifies a path. These paths must match the actual dataset locations. If the dataset is moved from the robot to a local PC or cloud server to improve training speed, update the paths for both train and val accordingly.

The converter will generate an XML file in the ~/my_data folder. This file is used to locate the path produced by the current dataset split. The final argument in the command, ~/my_data/data.yaml, can be changed to modify the save path. Remember the path to this file, as it will be used later for model training.

NOTE

    1. Start the robot and connect to it through VNC Viewer.

1. What should be done if training repeatedly fails?

Use the following procedure:

bash
sudo swapoff /swapfile

sudo rm /swapfile

sudo fallocate -l 6G /swapfile

sudo mkswap /swapfile

(2) Return to 10.4.3 Training the Model and continue with the training procedure.

10.5 Troubleshooting ​

Q1: Model Fails to Load

Possible causes include an incorrect model path, a corrupted model file, or an incompatible TensorRT version.

Solutions:

1. Confirm that the model file exists at the specified path.

2. Download or copy the model file again.

3. Check compatibility between the TensorRT version and the model.

Q2: Poor Detection Results After Training

Possible causes include insufficient training data, too few training epochs, or unsuitable model parameters.

Solutions:

1. Increase the size and diversity of the training dataset.

2. Increase the number of training epochs.

3. Adjust hyperparameters such as the learning rate and batch size.

Q3: Incorrect Dataset Path

Possible causes include a misspelled path in the configuration file or an incorrectly placed dataset.

Solutions:

1. Check the path entries in the dataset configuration file.

  1. Confirm that the dataset uses the required train/val/test directory structure.

3. Use absolute paths when relative paths cannot be resolved reliably.

Q4: Training Is Interrupted

Possible causes include insufficient memory, insufficient disk space, or a power interruption.

Solutions:

1. Reduce the batch size to lower memory usage.

2. Free disk space and confirm that sufficient storage is available.

3. Resume training from a checkpoint.
