Different light sources can change the apparent color of an object, which can produce differences in color-based recognition. If these differences affect feature performance, the color thresholds must be adjusted to compensate for the current environment. This section introduces the LAB Tool used to address this issue.

8.1.2 Adjusting a Color Threshold ​

1. Open the LAB Tool and select the color to calibrate from the color list in the recognition adjustment area. This example uses red.

2. Set the min values of the L, A, and B components to 0, and set all max values to 255.

3. Place the colored object within the camera's field of view. Refer to the LAB color-space diagram and adjust the L, A, and B ranges toward the target color.

Red lies toward +a. Keep the A-component max value unchanged and increase its min value until the target object appears white in the processed image on the left and the remaining areas appear black.

4. Adjust the L and B components for the current environment. If the red object appears too light, increase the minimum lightness value L_min. If it appears too dark, decrease the maximum lightness value L_max. If the red object appears too warm, increase b_min. If it appears too cool, decrease b_max.

The following table describes the LAB threshold ranges.

Color ComponentRangeCorresponding Color Axis
L0–255Black to white (−L to +L)
A0–255Green to red (−a to +a)
B0–255Blue to yellow (−b to +b)

5. Click Save Settings in the recognition adjustment area to save the color thresholds.

8.1.3 Adding a Recognition Color ​

In addition to the built-in colors, custom recognition colors can be added. The following procedure uses yellow as an example.

1. Open the LAB Tool and click Add Color.

2. Enter the color name in the Name field, then click OK.

3. Select the new color from the color list.

4. Place the colored object within the camera's field of view. Adjust the L, A, and B sliders until the target object appears white in the processed image on the left and the remaining areas appear black.

NOTE

For instructions on adjusting thresholds, see 8.1.2 Adjusting a Color Threshold.

5. Click Save Settings in the recognition adjustment area to save the color thresholds.

8.2 Color Recognition ​

This lesson uses OpenCV to recognize red, green, and blue objects and displays the recognition results in the camera feed.

Before starting, prepare one red, one green, and one blue object.

8.2.1 Overview ​

First, the program acquires an RGB image from the camera, resizes it, applies Gaussian blur, and converts it from RGB to the LAB color space.

It then uses color thresholds to identify the color of the object inside the target area and applies a mask to the image. A mask uses a selected image, shape, or object to hide all or part of the image being processed, limiting subsequent processing to the required area.

After morphological opening and closing, the program identifies the largest contour and draws a circle around the corresponding object.

Opening: Erodes and then dilates the image. This operation removes small objects and smooths object boundaries without significantly changing the target area.

It can remove small specks of noise and separate objects that are touching.

Erosion: Removes boundary pixels, contracts object boundaries, and eliminates objects smaller than the structuring element.

Dilation: Expands object boundaries by adding adjacent background pixels to the object.

Finally, the recognition result is overlaid on the camera feed.

#!/usr/bin/env python3
# encoding: utf-8
import os
import cv2
import qrcode
import numpy as np

def create_qrcode(data, file_name):
    '''
    version: An integer from 1 to 40 that controls the QR code size. Version 1 uses a 21 × 21 matrix.
             To determine the size automatically, set the value to None and use the fit parameter.
    error_correction: Controls QR-code error correction. Use one of the following four constants:
    　　ERROR_CORRECT_L: Corrects approximately 7% or less of damaged codewords.
    　　ERROR_CORRECT_M (default): Corrects approximately 15% or less of damaged codewords.
    　　ERROR_CORRECT_Q: Corrects approximately 25% or less of damaged codewords.
    　　ERROR_CORRECT_H: Corrects approximately 30% or less of damaged codewords.
    box_size: Controls the number of pixels in each QR-code module.
    border: Controls the number of modules in the border. The default is 4, which is the minimum specified by the standard.
    '''
    qr = qrcode.QRCode(
        version=1,
        error_correction=qrcode.constants.ERROR_CORRECT_H,
        box_size=5,
        border=4)
    # Add data
    qr.add_data(data)
    # Fill data
    qr.make(fit=True)
    # Generate image
    img = qr.make_image(fill_color=(0, 0, 0), back_color=(255, 255, 255))
    opencv_img = cv2.cvtColor(np.asarray(img), cv2.COLOR_RGB2BGR)
    while True:
        cv2.imshow('img', opencv_img)
        k = cv2.waitKey(1)
        if k != -1:
            break
    cv2.imwrite(file_name, opencv_img)
    print('save', data, file_name)

if __name__ == '__main__':
    file_path = os.getcwd()
    out_img = file_path + '/myQRcode.jpg'
    qrcode_text = input("Please enter：")
    create_qrcode(qrcode_text, out_img)

#!/usr/bin/env python3
# encoding: utf-8
import os
import queue
import rclpy
import threading
import numpy as np
from rclpy.node import Node
from cv_bridge import CvBridge
from sensor_msgs.msg import Image
from pyzbar import pyzbar
import cv2

class QRCodeDetectNode(Node):
    def __init__(self, name):
        rclpy.init()
        super().__init__(name)
        self.running = True
        self.bridge = CvBridge()
        self.image_queue = queue.Queue(maxsize=2)
        self.image_sub = self.create_subscription(Image, '/ascamera/camera_publisher/rgb0/image', self.image_callback, 1)
        threading.Thread(target=self.main, daemon=True).start()

    def image_callback(self, ros_image):
        cv_image = self.bridge.imgmsg_to_cv2(ros_image, "bgr8")
        bgr_image = np.array(cv_image, dtype=np.uint8)
        if self.image_queue.full():
            self.image_queue.get()
        self.image_queue.put(bgr_image)

(2) Decode the QR code and draw its boundary

The pyzbar library decodes the QR code, and OpenCV draws the boundary and decoded data.

python
            decoded_objects = pyzbar.decode(image)
            for obj in decoded_objects:
                points = obj.polygon
                if len(points) > 4:
                    hull = cv2.convexHull(np.array([point for point in points], dtype=np.float32))
                    points = hull.reshape(-1, 2)
                for j in range(len(points)):
                    cv2.line(image, tuple(points[j]), tuple(points[(j+1) % len(points)]), (0, 255, 0), 3)

            if key == ord('q') or key == 27:

tuple(points[(j+1) % len(points)]): The next vertex. The modulo operation connects the final vertex back to the first.

(0, 255, 0): The line color in BGR format. This value is green.

3: The line width in pixels.

8.4.2 Sensor-Based Line Following ​

This feature uses the 4-channel line follower sensor to detect a track. The controller calculates the robot's offset from the track and uses PID control to adjust the chassis angular velocity in real time. At intersections, the robot can continue straight, turn, make a U-turn, or stop according to the default logic or a received route command.

8.4.2.1 Overview ​

1. The program creates the 4-channel line follower sensor object with sdk.FourInfrared and periodically calls readData() to read the four channels.

2. The controller converts the raw sensor data into line-following states. It assigns position weights of -3, -1, 1, and 3 in the channel order used by the code and calculates the current error. An error of 0 indicates that the track is centered under the sensor. A change toward either side causes a corresponding steering correction.

3. The PID controller uses 0 as the setpoint, outputs chassis angular velocity from the error, and controls forward speed. If no valid line state is detected, the node publishes a zero-velocity command to prevent uncontrolled forward motion.

4. The program confirms an intersection across multiple frames to prevent false triggering. In default mode, the robot pauses briefly and turns right. In route-receive mode, it executes C for continue straight, R for turn right, L for turn left, U for a U-turn, and S for stop in sequence.

NOTE

The main() loop performs control only when a valid target has been detected and self.start is True. 8.6 Basic Line-Following Transport ​

8.6.1 Overview ​

The line_follow_transport supervisor node coordinates the sensor-based line-following node, line_follow, and the vision-based pick-up node, color_track_pick, to perform a continuous transport task: follow the line, pick up an object, continue following the line, and place the object at an intersection.

When the task starts, the supervisor sets the default target color to red, red, starts the color-tracking pick-up module, and starts the sensor-based line-following module after a 2-second delay. While the robot follows the prepared track, the camera searches for the target color. If no route is configured, the program sends stop_next_road after a successful pick-up, causing the robot to stop at the next sensor-confirmed intersection and place the object on the ground. Alternatively, configure a route consisting of C for continue straight, R for turn right, L for turn left, U for a U-turn, and S for stop. The robot then follows the specified route before placing the object.

This feature combines 4-channel sensor-based line following, LAB color recognition, chassis motion control, robotic-arm gripper control, and ROS 2 topic and service communication.

NOTE

This feature uses the 4-channel line follower sensor, rather than the camera, for line following. Before starting, make sure the track, red target object, and intersections are within the robot's reliable detection and operating range.

8.7 Vision-Based Tracking and Pick-Up ​

8.7.1 Overview ​

A state machine controls the search and pick-up sequence. The primary states are listed below:

StateFunction
COLOR_INITIAL_CHECKChecks the current image first, avoiding an unnecessary scan when the target is already in front of the robot.

COLOR_BASE_ALIGNRecenters the pan-tilt after finding the target and turns the chassis according to the pan-tilt offset.
COLOR_ALIGNAligns horizontally, then approaches the target slowly.
COLOR_WAIT_REACQUIREPauses after a brief target loss and waits for reacquisition or another scan.

The program requires the target to be detected for 3 consecutive frames before alignment begins. After 3 consecutive missed detections, it pauses and waits for reacquisition. If the target remains undetected for more than 2 seconds, scanning resumes. These limits reduce unintended motion caused by single-frame noise or brief occlusion.

In COLOR_ALIGN, the program first checks the target's horizontal error. If the error is greater than 28, the robot only rotates to align. It moves forward only after the target is near the image centerline, preventing the target from leaving the field of view when the short-wheelbase chassis turns while moving forward:

The robotic arm and gripper are controlled through SetPWMServoState messages. _set_servos() combines one or more servo IDs, target pulse widths, and movement durations into a message and publishes it to /ros_robot_controller/pwm_servo/set_state:

python
def _set_servos(self, *servos, duration=0.1):
    message = SetPWMServoState()
    message.duration = float(duration)
    for servo_id, position in servos:
        state = PWMServoState()
        state.id = [int(servo_id)]
        state.position = [int(position)]
        state.offset = [0]
        message.state.append(state)
    self.pwm_pub.publish(message)

For direct ground placement, the node enters DROP_DOWN: the robotic arm lowers, the gripper opens, and the arm returns to its initial pose before the node returns to IDLE.

For face-guided handover, the node proceeds through HEAD_CAMERA_RAISE, HEAD_SCANNING, HEAD_ALIGN, and the placement states. MediaPipe detects the largest face in the image. When no face is detected, the chassis rotates to continue searching. After a face is detected, the PID controller aligns its center with the image reference position. The buzzer sounds when alignment is complete. The robot moves forward approximately 0.05 m at 0.10 m/s, opens the gripper, and then reverses the same distance.

After either ground placement or face-guided handover, the program stops the chassis, clears the holding state, restores the initial pan-tilt and robotic-arm poses, and returns to IDLE.

8.8 Troubleshooting ​

Q1: Color recognition is inaccurate.

Possible causes: The color threshold has not been calibrated, ambient lighting has changed, or the camera image is out of focus.

Solutions:

1. Use the LAB Tool to recalibrate the color threshold. See 8.1.2 Adjusting a Color Threshold.

2. Ensure that the recognition area has adequate, stable lighting.

3. Rotate the camera lens manually to adjust the focus until the image is clear.

Q2: The camera image is black.

Possible causes: The camera is disconnected, the camera service is not running, or the USB connector is loose.

Solutions:

1. Check that the camera's USB cable is connected securely.

2. Run the following command to start the camera:

bash
ros2 launch peripherals depth_camera.launch.py

3. Disconnect and reconnect the camera's USB cable.

Q3: Mask processing produces no visible result.

Possible causes: The color-threshold range is incorrect, or an image-preprocessing step is missing.

Solutions:

1. Recalibrate the LAB color threshold and confirm that the target area appears white. See 8.1.2 Adjusting a Color Threshold.

2. Confirm that Gaussian blur, erosion, and dilation are performed correctly. See 8.2.4 Program Analysis.

3. Check that the input image format used for masking is correct.

Q4: The program runs out of memory.

Possible causes: The program has not released resources, or multiple programs are running simultaneously.

Solutions:

1. Close unnecessary programs to free memory.

2. Restart the robot to clear residual processes.

Q5: Sensor-based line following performs poorly.

Possible cause: The 4-channel line follower sensor has not been calibrated.

Solution:

1. Power on the robot and wait until startup is complete.

2. Place the robot over the black track, then position the leftmost sensor directly above the track.

3. Slowly adjust the black potentiometer above that channel until its blue indicator turns off over the black track and turns on away from the black track. This indicates that the channel has been calibrated.

4. Repeat Step 3 for each of the remaining three channels until all four channels are calibrated.
