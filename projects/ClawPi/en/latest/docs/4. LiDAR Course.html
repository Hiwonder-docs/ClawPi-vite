4. LiDAR Course ​

4.1 Introduction to LiDAR ​

4.1.1 Overview ​

LiDAR, short for Light Detection and Ranging, uses laser light to detect and measure the surrounding environment. It emits laser pulses and analyzes the reflected signals to determine an object's distance, velocity, and shape. With its high accuracy, high resolution, and fast response, LiDAR is widely used in autonomous vehicles, robot navigation, 3D mapping, and environmental monitoring.

LiDAR sensors can be classified by measurement principle as triangulation, pulsed time-of-flight, or coherent LiDAR. ClawPi uses a pulsed time-of-flight LiDAR sensor.

This section uses the Guoke Optics COIN-D6 single-line LiDAR. The COIN-D6 uses TOF, or time-of-flight, ranging and a 940 nm VCSEL laser. It provides strong resistance to ambient-light interference of up to 30 klux and can be used indoors and outdoors. The COIN-D6 communicates over 100 Mbps Ethernet using UDP, providing high data-transfer rates and low latency.

The COIN-D6 LiDAR is shown below.

4.1.2 How LiDAR Works ​

A LiDAR sensor consists of a laser emitter, a scanning system, a laser receiver, and a signal-processing system.

The laser emitter first directs a laser beam toward the target. The scanning system sweeps the beam across a plane to collect a two-dimensional profile of the surroundings.

The laser receiver then receives the laser light reflected by the target and generates a received signal.

Finally, the signal-processing system processes the received signal to obtain characteristics of the target, including its surface geometry and physical properties, such as target bearing, height, and velocity. These characteristics are then used to construct a model of the object.

The COIN-D6 LiDAR uses a 940 nm VCSEL laser emitter and an APD receiver. A built-in motor drives 360° rotational scanning. At 400 rpm, each revolution can collect approximately 2,163 measurement points. Each measurement point contains distance, angle, confidence, and peak-value data.

4.2 Operating Principle and Ranging Methods ​

4.2.1 Distance Measurement ​

LiDAR sensors commonly use one of two methods to measure distance: triangulation or TOF.

The COIN-D6 uses TOF, or time-of-flight, ranging. It calculates the distance to a target from the time between emitting a laser pulse and receiving its reflection.

As shown below, the LiDAR directs a laser pulse at an object, and the object reflects the light back to the LiDAR. The sensor measures the round-trip travel time of the light. Multiplying this time by the speed of light and dividing by 2 gives the distance between the object and the LiDAR.

Distance D = c × Δt / 2

Here, c is the speed of light, approximately 3 × 10⁸ m/s, and Δt is the round-trip travel time of the laser pulse.

Triangulation is illustrated below. During sensor design, the laser beam is set to illuminate the object at a fixed angle rather than directly. This angle is preset and remains unchanged during operation, so trigonometric functions can be used with the known angle to calculate the distance from the LiDAR to the object.

4.3.2.1 Initialization ​

python
class LidarController(Node):
    def __init__(self, name):
        rclpy.init()
        super().__init__(name)

        self.name = name
        self.running_mode = 0
        self.threshold = 0.6  # meters
        self.scan_angle = math.radians(360)  # radians
        self.speed = 0.2
        self.last_act = 0
        self.timestamp = 0
        self.angle_data = []
        # PID parameters
        self.pid_yaw = pid.PID(6.6, 0, 0.01)
        self.pid_dist = pid.PID(1.7, 0, 0.16)
        self.lock = threading.RLock()
        self.lidar_sub = None
        self.lidar_type = os.environ.get('LIDAR_TYPE')
        self.machine_type = os.environ.get('MACHINE_TYPE')

self.name: Stores the name passed to the object.

The remaining attributes define LiDAR control parameters such as the operating mode, detection threshold, scan angle, and speed.

self.lock: Creates a reentrant lock for thread-safe access to shared data.

Key Variables

The following variables are used by the mode-control logic:

  • left_range / right_range: Distance arrays, in meters, created by dividing the 360° scan into left and right sectors in the LiDAR callback.

  • twist: A ROS 2 geometry_msgs/Twist message. linear.x controls forward and backward velocity, while angular.z controls angular velocity about the Z-axis.

  • mecanum_pub: Publishes velocity commands for the Mecanum chassis. The chassis controller subscribes to these commands.

PID Controller Parameters

  • pid_yaw: Yaw PID controller used to steer the robot.

    • P = 6.6: Proportional gain that responds to the current angular error.
    • I = 0: Integral gain. A value of zero means that historical error is not accumulated.
    • D = 0.01: Derivative gain that reduces steering overshoot and oscillation.

  • pid_dist: Distance PID controller used for forward and backward motion in LiDAR following mode.

    • P = 1.7: Proportional gain.
    • I = 0: Integral gain.
    • D = 0.16: Derivative gain.

LiDAR Model Compatibility

Different LiDAR models scan in different directions:

  • COIN-D6 and similar models: Scan counterclockwise, matching the positive angular direction of the ROS coordinate system.

  • G4: Scans clockwise, so the angular direction must be inverted.

The code uses self.lidar_type to identify the LiDAR model and negates the angle values for the G4. It also applies different angular-velocity limits: ±8 times the base speed for non-G4 models and ±4 times the base speed for the G4.

4.4.2 Function Implementation ​

This example uses a bookend as the obstacle. When using LiDAR obstacle avoidance, the object must extend above the LiDAR scan plane so that the LiDAR mounted on ClawPi can reliably detect the obstacle's position. While ClawPi is moving straight ahead, if the detected obstacle is closer than the 0.6 m threshold, the robot automatically turns to avoid it.

4.4.3 Program Parameters ​

4.4.3.1 Obstacle-Avoidance Logic ​

Based on the implemented behavior, the program flow can be summarized as shown in the flowchart below:

  • LiDAR Obstacle Avoidance
python
                if self.running_mode == 1 and self.timestamp <= time.time():
                    left_nonzero = left_range.nonzero()
                    right_nonzero = right_range.nonzero()
                    left_nonan = np.isfinite(left_range[left_nonzero])
                    right_nonan = np.isfinite(right_range[right_nonzero])
                    min_dist_left_ = left_range[left_nonzero][left_nonan]
                    min_dist_right_ = right_range[right_nonzero][right_nonan]
                    # Find the nearest distances on the left and right
                    if len(min_dist_left_) > 1 and len(min_dist_right_) > 1:
                        min_dist_left = min_dist_left_.min()
                        min_dist_right = min_dist_right_.min()
                        # Obstacle on the left
                        if min_dist_left <= self.threshold and min_dist_right > self.threshold:  
                            # Keep the forward velocity as low as possible while turning
                            twist.linear.x = self.speed / 6  
                            # Turn 90 degrees
                            max_angle = math.radians(90)  
                            # Keep the turning speed as high as possible
                            w = self.speed * 6.0  
                            twist.angular.z = -w
                            if self.last_act != 0 and self.last_act != 1:
                                twist.angular.z = w
                            self.last_act = 1
                            self.mecanum_pub.publish(twist)
                            self.timestamp = time.time() + (max_angle / w / 2)
                        elif min_dist_left <= self.threshold and min_dist_right <= self.threshold:  # Obstacles on both sides
                            # Keep the forward velocity as low as possible while turning
                            twist.linear.x = self.speed / 6  
                            # Keep the turning speed as high as possible
                            w = self.speed * 6.0  
                            twist.angular.z = w
                            self.last_act = 3
                            self.mecanum_pub.publish(twist)
                            # Turn 180 degrees
                            self.timestamp = time.time() + (math.radians(180) / w / 2)
                            # Obstacle on the right
                        elif min_dist_left > self.threshold and min_dist_right <= self.threshold:  
                            # Keep the forward velocity as low as possible while turning
                            twist.linear.x = self.speed / 6  
                            # Turn 90 degrees
                            max_angle = math.radians(90) 
                            # Keep the turning speed as high as possible
                            w = self.speed * 6.0  
                            twist.angular.z = w
                            if self.last_act != 0 and self.last_act != 2:
                                twist.angular.z = -w
                            self.last_act = 2
                            self.mecanum_pub.publish(twist)
                            self.timestamp = time.time() + (max_angle / w / 2)
                            # No obstacles
                        else: 
                            self.last_act = 0
                            twist.linear.x = self.speed  # Move straight
                            self.mecanum_pub.publish(twist)

The program finds the minimum distances on the left and right, min_dist_left and min_dist_right, and compares them with self.threshold. If an obstacle is detected only on the left, the robot turns 90° to the right. If obstacles are detected on both sides, it turns 180°. If an obstacle is detected only on the right, it turns 90° to the left. If no obstacle is detected, it continues forward. self.last_act stores the previous action to prevent repeated turns.

Turn-Duration Calculation

self.timestamp = time.time() + (max_angle / w / 2)

  • max_angle: Target turn angle, such as 90° = π/2 rad.

  • w: Angular velocity in rad/s.

  • max_angle / w: The theoretical time required for pure rotation.

  • / 2: Because forward motion is applied at the same time, the code uses approximately half of the pure-rotation duration for the combined motion.

This timing gate prevents the obstacle detector from triggering repeatedly during a turn. Normal detection resumes when the turn is complete.

4.5.2 Function Implementation ​

This example uses a bookend as the target. When using LiDAR following, the object must extend above the LiDAR scan plane so that the LiDAR mounted on ClawPi can reliably detect its position. ClawPi then adjusts its own position so that the distance between the robot and the object remains at approximately 0.3 m, which is half of the configured threshold.

4.5.3 Program Parameters ​

4.5.3.1 Following Logic ​

Based on the implemented behavior, the program flow can be summarized as shown in the figure below:

LiDAR Following

python
                elif self.running_mode == 2:
                    # Merge distance data from the right half counterclockwise to the left half
                    ranges = np.append(right_range[::-1], left_range)
                    # self.get_logger().info(str(ranges))
                    nonzero = ranges.nonzero()
                    nonan = np.isfinite(ranges[nonzero])
                    dist_ = ranges[nonzero][nonan]
                    if len(dist_) > 0:
                        dist = dist_.min()
                        min_index = list(ranges).index(dist)
                        angle = -angle + lidar_data.angle_increment * min_index  # Calculate the angle corresponding to the minimum distance
                        # self.get_logger().info(str(dist_))
                        # self.get_logger().info(str([dist, angle]))
                        if dist < self.threshold and abs(math.degrees(angle)) > 5:  # Control left/right steering
                            if self.lidar_type != 'G4':
                                self.pid_yaw.update(-angle)
                                twist.angular.z = common.set_range(self.pid_yaw.output, -self.speed * 8.0, self.speed * 8.0) 
                            elif self.lidar_type == 'G4':
                                self.pid_yaw.update(angle)
                                twist.angular.z = -common.set_range(self.pid_yaw.output, -self.speed * 4.0, self.speed * 4.0) 
                        else:
                            self.pid_yaw.clear()

                        if dist < self.threshold and abs(0.2 - dist) > 0.02:  # Control forward/backward motion
                            self.pid_dist.update(self.threshold / 2 - dist)
                            twist.linear.x = common.set_range(self.pid_dist.output, -self.speed, self.speed)
                        else:
                            self.pid_dist.clear()
                        if abs(twist.angular.z) < 0.08:
                            twist.angular.z = 0.0
                        if abs(twist.linear.x) < 0.01:
                            twist.linear.x = 0.0
                        self.mecanum_pub.publish(twist)

The program combines the left and right distance readings into the ranges array to form a circular scan. It removes zero-distance values with nonzero() and excludes invalid NaN and Inf values with isfinite(), producing the valid-distance array dist_. It then takes the minimum value dist from dist_, finds its index min_index in ranges, and calculates the angle angle of the nearest object.

Steering control: If dist is below the threshold and the target is more than 5° away from the forward direction, the PID controller calculates an angular velocity that turns the robot toward the target. The G4 and non-G4 models use opposite steering directions and different output limits: ±8 times the base speed for non-G4 models and ±4 times the base speed for the G4.

Distance control: When dist is below the threshold and differs from 0.2 m by more than 0.02 m, the code enables distance PID control. The PID controller uses self.threshold / 2, or 0.3 m, as the target distance and calculates the linear velocity required to move the robot forward or backward.

Finally, dead zones are applied to the angular and linear velocities, with angular < 0.08 and linear < 0.01, to prevent jitter from very small commands. The resulting Twist command is then published.

This allows the LiDAR mounted on the ClawPi robot to effectively detect the object's position. ClawPi then adjusts its overall orientation so that the robot faces the obstacle, with the camera pointing directly toward it.

The program combines the left and right LiDAR readings into the ranges array to form a circular scan. It then calculates the minimum distance, dist, and the corresponding angle, angle. If dist is below the threshold and the target is more than 5° away from the forward direction, the yaw PID controller calculates the required angular velocity, twist.angular.z, and publishes the resulting Twist command.

Unlike LiDAR following, LiDAR guard only rotates the robot toward the detected object about the yaw axis. It does not control the forward distance, so pid_dist and twist.linear.x are not used.

4.7 Troubleshooting ​

Q1: No LiDAR Data Is Published

Possible causes: The LiDAR is not connected correctly, or the LiDAR driver is not running.

Solutions:

1. Check that the LiDAR USB connection is secure. Disconnect and reconnect it if necessary.

2. Confirm that ros2 launch peripherals lidar.launch.py has been run to start the LiDAR driver.

3. Run ros2 topic echo /scan to check whether scan data is being published.

Q2: Obstacle Avoidance Is Not Responsive

Possible causes: The threshold is set too high or too low, or the LiDAR scan angle is unsuitable.

Solutions:

1. Check the obstacle-detection threshold. The default is 0.6 m. Adjust it for the operating environment if necessary.

2. Make sure the target extends above the LiDAR scan plane.

3. Make sure nothing obstructs the LiDAR sensor.

Q3: The Mode-Switching Command Fails

Possible causes: The service call is incorrect, or the parameters are not formatted correctly.

Solutions:

1. Make sure LiDAR mode has been entered by calling the enter service.

2. Check the command syntax, including capitalization and spaces.

3. Run ros2 service list to display the available services.

Q4: A Service Call Returns an Error

Possible causes: The service name is incorrect, the service type does not match, or the node is not running.

Solutions:

1. Run ros2 service list and verify the service name.

2. Make sure the service type, such as std_srvs/srv/Trigger, matches the call command.

3. Make sure the corresponding launch file is running.

Q5: The LiDAR Scan Range Is Incorrect

Possible causes: The LiDAR is obstructed, or the configured LiDAR model is incorrect.

Solutions:

1. Check for objects around the LiDAR that could block the scan.

2. Make sure the configured LiDAR model matches the installed COIN-D6.

3. Visualize the scan in RViz to inspect the LiDAR output.
