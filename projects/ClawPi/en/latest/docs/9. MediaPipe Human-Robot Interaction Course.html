9. MediaPipe Human-Robot Interaction Course ​

9.1 MediaPipe Overview and Getting Started ​

9.1.1 MediaPipe Overview ​

MediaPipe is an open-source multimedia machine-learning model application framework. It runs across mobile devices, workstations, and servers and supports mobile GPU acceleration. It also supports TensorFlow and TF Lite inference engines, allowing TensorFlow and TF Lite models to be used with MediaPipe. On mobile and embedded platforms, MediaPipe can also use the device's GPU for acceleration.

NOTE

The ClawPi examples in this chapter use the legacy mp.solutions.hands and mp.solutions.pose APIs. Current Google documentation centers on MediaPipe Tasks. Do not mix the two APIs when maintaining the existing programs.

9.1.2 MediaPipe Advantages and Limitations ​

  • MediaPipe Advantages

    1. Supports multiple platforms and languages, including iOS, Android, C++, Python, JavaScript, and Coral.

    2. Runs quickly, and most models can operate in real time.

    3. Provides a high level of reuse for both models and code.

  • MediaPipe Limitations

    1. On mobile devices, MediaPipe is relatively large and requires at least 10 MB of storage space.

    2. MediaPipe depends heavily on TensorFlow. Replacing it with another machine-learning framework requires extensive code changes.

    3. MediaPipe uses static graphs. This helps improve efficiency but can make errors difficult to locate.

9.1.3 MediaPipe Workflow ​

The following diagram shows the MediaPipe workflow. Solid lines represent steps that require application code, while dashed lines represent steps that do not need to be implemented manually. MediaPipe already integrates AI-related models, allowing the framework required for a feature to be assembled quickly.

  • Dependencies

MediaPipe depends on OpenCV for video processing and FFmpeg for audio-data processing. Other dependencies include OpenGL or Metal, TensorFlow, and Eigen.

  • MediaPipe Solutions

MediaPipe Solutions are open-source prebuilt examples based on specific pretrained TensorFlow or TFLite models. MediaPipe Solutions are built on top of the MediaPipe framework. The legacy Solutions framework described here provides 16 Solutions, including face detection, Face Mesh, iris, hand, pose, and human-body solutions.

9.2 Fingertip Trajectory Tracking ​

This feature uses the MediaPipe hand-detection model to identify hand landmarks. After recognizing a specified gesture, the robot begins locking onto the fingertip, tracks it, and draws the fingertip trajectory in the camera feed.

9.2.1 Operating Principle ​

First, the program acquires camera frames and runs the MediaPipe hand-landmark detector.

It then flips and preprocesses each frame, detects the hand information, and uses the connections between the hand landmarks to calculate finger angles and determine the gesture.

When the specified gesture is detected, the program locks onto the fingertip and draws its movement trajectory in the live camera feed.

The camera acquires each frame and preprocesses it through color-space conversion to make recognition easier. The following flowchart summarizes the program logic.

The program logic is organized mainly around the initialization function and the image-processing function. Items marked with an asterisk are especially important. The following analysis follows the sequence shown in the flowchart.

  • Initialization Function (__init__(self, name))

The initialization function of the HandTrajectoryNode class is the starting point for defining the basic parameters. The main items are the drawing utility and the hand-feature detector.

(1) Define the drawing utility (self.drawing):

python
 self.drawing = mp.solutions.drawing_utils

self.drawing is the drawing utility used to render detected hand landmarks and connect the corresponding key points. mp refers to the MediaPipe recognition module used to extract hand features, and drawing_utils provides the drawing functions.

(2) Define the hand-feature detector (self.hand_detector):

python
        self.hand_detector = mp.solutions.hands.Hands(
            static_image_mode=False,
            max_num_hands=1,
            min_tracking_confidence=0.05,
            min_detection_confidence=0.6
        )

self.hand_detector is the hand-feature detector. mp also represents the MediaPipe recognition module, and hands.Hands is the module used to extract hand features. The following parameters require particular attention:

ParameterDescription
static_image_modeWhen False, the detector treats the input as a video stream and tracks detected hands between frames.
max_num_handsMaximum number of hands to detect. The source code sets this value to 1.
min_tracking_confidenceMinimum tracking-confidence threshold. If tracking confidence is insufficient, the detector runs hand detection again.
min_detection_confidenceMinimum confidence required for a hand detection to be accepted. The value range is 0.0–1.0.

After the basic tool parameters have been defined, the program enters the logical recognition stage. The following analysis covers the main code from the initial image preprocessing step (color-space conversion) through to the final fingertip-trajectory rendering process.

(1) Convert the image color space

python
image_flip = cv2.cvtColor(cv2.flip(image, 1), cv2.COLOR_BGR2RGB)

The input image is converted to the required color space to improve recognition accuracy. The program uses cv2.cvtColor with cv2.COLOR_RGB2BGR for the RGB and BGR conversion and stores the converted image in bgr_image. Keep these parameters at their default settings.

(2) Store the landmark-detection result

python
 results = self.hand_detector.process(image_flip)

self.hand_detector.process() extracts the hand landmarks and stores their image positions in results for subsequent logic.

(3) Configure landmark rendering

python
                        self.drawing.draw_landmarks(
                            result_image,
                            hand_landmarks,
                            mp.solutions.hands.HAND_CONNECTIONS)

After the key points are detected, the drawing utility is configured to draw the hand landmarks and their connections. bgr_image is the input image, hand_landmarks contains the detected hand key points, and HAND_CONNECTIONS defines how those points are connected according to the standard hand-landmark indices.

(4) Calculate finger angles (thumb, index finger, and others)

python
def hand_angle(landmarks):
    """
    Calculate the bending angle of each finger.
    :param landmarks: Hand landmarks.
    :return: The angle of each finger.
    """
    angle_list = []
    # Thumb
    angle_ = vector_2d_angle(landmarks[3] - landmarks[4], landmarks[0] - landmarks[2])
    angle_list.append(angle_)
    # Index finger
    angle_ = vector_2d_angle(landmarks[0] - landmarks[6], landmarks[7] - landmarks[8])
    angle_list.append(angle_)
    # Middle finger
    angle_ = vector_2d_angle(landmarks[0] - landmarks[10], landmarks[11] - landmarks[12])
    angle_list.append(angle_)
    # Ring finger
    angle_ = vector_2d_angle(landmarks[0] - landmarks[14], landmarks[15] - landmarks[16])
    angle_list.append(angle_)
    # Little finger
    angle_ = vector_2d_angle(landmarks[0] - landmarks[18], landmarks[19] - landmarks[20])
    angle_list.append(angle_)
    angle_list = [abs(a) for a in angle_list]
    return angle_list

After the hand landmarks are stored in results, the program processes the geometric relationships between the key points. hand_angle() receives the landmarks set and calls vector_2d_angle() to calculate the corresponding angles for the thumb, index finger, and remaining fingers. The landmark indices are shown below.

For the thumb, vector_2d_angle() calculates the angle from landmark points 3, 4, 0, and 2 shown in the hand-landmark diagram. This angle represents the thumb pose. The remaining fingers use the same principle with their corresponding landmark points.

Keep the parameters and basic angle-calculation logic in hand_angle() at their default settings to maintain recognition performance.

After the finger types and their positions in the image are determined, h_gesture() applies logical conditions to classify different hand gestures.

In h_gesture(), the thresholds include thr_angle = 65 and thr_angle_thumb = 53.

Together with thr_angle_s = 49, these three values define the angle thresholds used for gesture classification. Testing shows relatively stable recognition at these values, so changes are not recommended. If recognition is poor, adjust them only within approximately ±5. angle_list[0] through angle_list[4] correspond to the five fingers.

The one gesture is used as an example:

python

The code classifies one by comparing all five finger angles with the configured thresholds. It checks whether the thumb angle is greater than 5, whether the index-finger angle is below thr_angle_s, and whether the middle, ring, and little-finger angles meet the thr_angle conditions shown in the code. When all conditions are satisfied, the gesture is classified as one. Other gestures use the same type of threshold-based logic.

Each gesture uses different threshold conditions, but the overall classification structure is the same. Refer to the preceding analysis for the other gesture features.

(6) Detect the fingertip, draw the trajectory, and clear the trajectory

The following code detects the fingertip gesture:

python
                    if self.state != State.TRACKING:
                        if gesture == "one":  # Detect index finger gesture and start fingertip tracking
                            self.count += 1
                            if self.count > 5:
                                self.count = 0
                                self.state = State.TRACKING
                                self.points = []
                        else:
                            self.count = 0

When one is detected, self.count records how many consecutive frames the gesture is maintained. The gesture is confirmed after it has been maintained for the required number of frames; a typical setting is about 5–7 frames, while an excessively large value can reduce recognition responsiveness. The program then sets the current gesture state to TRACKING, allowing tracking to begin, and initializes self.points for the positions of adjacent points and points_list for the feature-point collection used to draw the trajectory.

The following code draws the trajectory:

python
                    elif self.state == State.TRACKING:
                        if gesture != "two":
                            if len(self.points) > 0:
                                last_point = self.points[-1]
                                if distance(last_point, index_finger_tip) < 5:
                                    self.count += 1
                                else:
                                    self.count = 0
                                    self.points.append(index_finger_tip)
                            else:
                                self.points.append(index_finger_tip)
                        draw_points(result_image, self.points)

While tracking, the custom distance() function calculates the distance between the previous point and index_finger_tip. The threshold 5 represents the pixel distance between consecutive points. For faster movement, this value can be increased cautiously to maintain a reliable decision, but it is generally recommended not to exceed 10. A lower value can be used for slower movement. The fingertip coordinates are stored as pixel positions for trajectory drawing.

The following code clears the trajectory:

python
                    if gesture == "five":
                        self.state = State.NULL
                        self.points = []
                        draw_points(result_image, self.points)

When the five gesture is detected, the state is reset to NULL and the stored trajectory points are cleared.

This robot uses MediaPipe for hand-feature detection. MediaPipe is an open-source multimedia machine-learning model application framework that runs across mobile devices, workstations, and servers. The PID controllers update the X- and Z-axis servo positions.

                self.pid_y.SetPoint = self.center.width / 2

9.4 Person Tracking ​

This feature uses a YOLO object-detection model to detect a person in the camera feed and combines PID control to adjust the pan-tilt direction and chassis motion in real time, allowing the robot to follow the person automatically.

9.4.1 Operating Principle ​

First, the program acquires the live camera feed and uses YOLO to detect objects whose target class is person.

It calculates the offset between the detected target center and the frame center, then uses PID control to calculate the pan-tilt and chassis commands.

Finally, the program publishes servo commands to adjust the pan-tilt direction and chassis motion commands to move the robot forward, backward, left, or right, enabling real-time person tracking.

9.4.3 Expected Result ​

After the feature starts, the robot enters person-tracking mode. When a person is detected in the camera feed, the robot automatically adjusts the pan-tilt to keep it oriented toward the person and follows the person as they move.

When the person moves horizontally in the frame, the pan-tilt turns left or right. When the person moves closer or farther away, the chassis moves backward or forward to maintain tracking.

9.4.4 Program Overview ​

Section 9.4.2 Starting and Stopping the Feature starts the feature with the following command:

bash
ros2 launch example body_track.launch.py

The entry point is body_track.launch.py. This ROS 2 launch file declares launch arguments, loads the camera and controller, and starts the YOLO and person-tracking nodes. It does not implement detection, target selection, or motion-control algorithms directly.

NOTE

Back up the factory program before changing the launch file or its arguments. Keep argument names, default values, and data types consistent so that each node receives valid configuration data.

  • Runtime Mode and Package Paths

The program checks the need_compile environment variable to determine whether it is running from an installed build or from source, then resolves the peripherals and controller package paths accordingly:

py
compiled = os.environ.get('need_compile', 'False')
if compiled == 'True':
    peripherals_package_path = get_package_share_directory('peripherals')
    controller_package_path = get_package_share_directory('controller')
else:
    peripherals_package_path = '/home/ubuntu/ros2_ws/src/peripherals'
    controller_package_path = '/home/ubuntu/ros2_ws/src/driver/controller'

When need_compile is True, the program uses the ROS 2 ament index to locate the installed package share directories. Otherwise, it uses the workspace source paths for development and debugging. os.environ.get() provides a default value of False if the environment variable is not set.

  • Launch Arguments

body_track.launch.py defines the following arguments with DeclareLaunchArgument:

  • camera_topic: Camera-image topic. The default is /image_raw. The value is passed to both the YOLO and person-tracking nodes.

  • model_name: YOLO model name. The default is yolo26n.

  • model_size: Model-size configuration. The default is 0.

  • conf: Detection-confidence threshold. The default is 0.5.

  • yolo_display: Whether to display the YOLO-node output. The default is false.

  • display: Whether to display the person-tracking output. The default is true.

  • target_class: Target class to track. The default is person.

Launch arguments are passed as text. ParameterValue converts numeric and Boolean values to the types expected by the nodes:

py

9.5 Body-Gesture Control ​

This feature uses a human-pose estimation model from the MediaPipe machine-learning framework. After detecting the human torso in the live camera feed, the program marks the relevant joint positions and recognizes multiple body movements, allowing the robot to be controlled through body gestures.

From the robot’s perspective, raising the left arm makes the robot move a short distance to the right, raising the right arm makes it move a short distance to the left, raising the left leg makes it move forward, and raising the right leg makes it move backward.

9.5.1 Operating Principle ​

First, the node loads the MediaPipe pose model and subscribes to the camera topic to obtain live frames.

MediaPipe is an open-source multimedia machine-learning model application framework. It runs across mobile devices, workstations, and servers and supports mobile GPU acceleration. It also supports TensorFlow and TF Lite inference engines.

Using the initialized model, the program detects the key landmarks of the human torso, draws the connections between those landmarks to show the torso structure, and then determines the body pose.

When a predefined gesture is recognized, the robot executes the corresponding movement.

def joint_distance(landmarks):
    distance_list = []

    d1 = landmarks[LEFT_HIP] - landmarks[LEFT_SHOULDER]
    d2 = landmarks[LEFT_HIP] - landmarks[LEFT_WRIST]
    dis1 = d1[0]**2 + d1[1]**2
    dis2 = d2[0]**2 + d2[1]**2
    distance_list.append(round(dis1/dis2, 1))
   
    d1 = landmarks[RIGHT_HIP] - landmarks[RIGHT_SHOULDER]
    d2 = landmarks[RIGHT_HIP] - landmarks[RIGHT_WRIST]

    dis2 = d2[0]**2 + d2[1]**2
    distance_list.append(round(dis1/dis2, 1))

    d2 = landmarks[LEFT_ANKLE] - landmarks[LEFT_KNEE]
    dis1 = d1[0]**2 + d1[1]**2
    dis2 = d2[0]**2 + d2[1]**2
    distance_list.append(round(dis1/dis2, 1))
   
    d1 = landmarks[RIGHT_HIP] - landmarks[RIGHT_ANKLE]
    d2 = landmarks[RIGHT_ANKLE] - landmarks[RIGHT_KNEE]
    dis1 = d1[0]**2 + d1[1]**2

7. Use PID control to calculate the pan-tilt correction and command the servos.

8. Control the gripper from the stable gesture state.

9. Draw and publish the recognition result.

vector_2d_angle：

def vector_2d_angle(v1, v2):
    """Same as sdk.common — arctan2 + cross product, returns [-180, 180]."""
    v1, v2 = np.asarray(v1), np.asarray(v2)
    d = np.linalg.norm(v1) * np.linalg.norm(v2)
    if d < 1e-8:
        return 65535.0
    cos = v1.dot(v2) / d
    sin = np.cross(v1, v2) / d
    return float(np.degrees(np.arctan2(sin, cos)))

Calculates the angle between two 2D vectors and returns a value in the range [-180, 180] degrees. It returns 65535.0 as an error marker when either vector length is close to zero.

hand_angle：

python
def hand_angle(landmarks):
    """Return 5 finger bend angles from 21 hand landmarks (pixel coords)."""
    angles = []
    # thumb: landmarks 4&rarr;0 vs 2&rarr;0
    angles.append(vector_2d_angle(
        (landmarks[4][0] - landmarks[0][0], landmarks[4][1] - landmarks[0][1]),
        (landmarks[2][0] - landmarks[0][0], landmarks[2][1] - landmarks[0][1])))
    # index: 0&rarr;6 vs 7&rarr;8
    angles.append(vector_2d_angle(
        (landmarks[0][0] - landmarks[6][0], landmarks[0][1] - landmarks[6][1]),
        (landmarks[7][0] - landmarks[8][0], landmarks[7][1] - landmarks[8][1])))
    # middle: 0&rarr;10 vs 11&rarr;12
    angles.append(vector_2d_angle(
        (landmarks[0][0] - landmarks[10][0], landmarks[0][1] - landmarks[10][1]),
        (landmarks[11][0] - landmarks[12][0], landmarks[11][1] - landmarks[12][1])))
    # ring: 0&rarr;14 vs 15&rarr;16
    angles.append(vector_2d_angle(
        (landmarks[0][0] - landmarks[14][0], landmarks[0][1] - landmarks[14][1]),
        (landmarks[15][0] - landmarks[16][0], landmarks[15][1] - landmarks[16][1])))
    # pinky: 0&rarr;18 vs 19&rarr;20
    angles.append(vector_2d_angle(
        (landmarks[0][0] - landmarks[18][0], landmarks[0][1] - landmarks[18][1]),
        (landmarks[19][0] - landmarks[20][0], landmarks[19][1] - landmarks[20][1])))
    return [abs(a) for a in angles]

Calculates the bend angles of all five fingers—the thumb, index finger, middle finger, ring finger, and little finger—from the pixel coordinates of the 21 hand landmarks. The returned angle list is used for subsequent gesture classification.

classify_gesture：

python
def classify_gesture(angle_list):
    """Exact thresholds from h_gesture() in hand_trajectory_node.py.
    Returns 'open', 'close', or 'none'."""
    THR_ANGLE = 65.          # finger bent
    THR_ANGLE_S = 49.        # finger extended
    THR_ANGLE_THUMB = 10.    # thumb relaxed

    a = angle_list
    if 65535.0 in a:
        return 'none'
    if (a[0] < THR_ANGLE_S and a[1] < THR_ANGLE_S and a[2] < THR_ANGLE_S and
            a[3] < THR_ANGLE_S and a[4] < THR_ANGLE_S):
        return 'open'
    if (a[0] > THR_ANGLE_THUMB and a[1] > THR_ANGLE and a[2] > THR_ANGLE and
            a[3] > THR_ANGLE and a[4] > THR_ANGLE):
        return 'close'
    return 'none'

Classifies the gesture from the five finger angles. If all angles are below THR_ANGLE_S at 49 degrees, the result is open. If all angles are above THR_ANGLE at 65 degrees, the result is close. Otherwise, the function returns none.

class ArmHandControl(Node):
    def __init__(self):
        super().__init__('arm_hand_control')
        self.bridge = CvBridge()

        # camera
        self.image_sub = self.create_subscription(
            Image, '/image_raw', self.image_callback, 1)

        # PWM servo publisher
        self.pwm_pub = self.create_publisher(
            SetPWMServoState, '/ros_robot_controller/pwm_servo/set_state', 10)

        # annotated image output
        self.result_pub = self.create_publisher(Image, '~/image_result', 1)

        # MediaPipe hands
        self.mp_hands = mp.solutions.hands
        self.hands = self.mp_hands.Hands(
            model_complexity=0,
            min_detection_confidence=0.5,
            min_tracking_confidence=0.5)
        self.mp_draw = mp.solutions.drawing_utils

        # PID controllers for pan-tilt
        self.pid_yaw = PID(P=0.1, I=0.000, D=0.000)
        self.pid_pitch = PID(P=0.1, I=0.000, D=0.000)

        # servo positions
        self.pitch_pos = PITCH_INIT
        self.yaw_pos = YAW_INIT
        self.arm_pos = ARM_INIT
        self.last_grip = GRIP_OPEN

        # gesture buffer
        self.gesture_buf = []
        self.gesture_stable = 'none'

        # hand center tracking
        self.hand_center = None  # (cx, cy) in pixels

        # image dimensions
        self.img_w, self.img_h = 640, 480

        # init all servos to center
        self._set_servos([SERVO_PITCH, PITCH_INIT],
                         [SERVO_YAW, YAW_INIT],
                         [SERVO_ARM, ARM_INIT],
                         [SERVO_GRIPPER, GRIP_OPEN],
                         duration=0.3)

        # processing loop
        self.image_queue = queue.Queue(maxsize=2)
        self.running = True
        threading.Thread(target=self.main_loop, daemon=True).start()

        self.get_logger().info('\033[1;32mArmHandControl ready\033[0m')

This class implements the gesture-controlled gripping node and inherits from the ROS 2 Node class. Initialization performs the following tasks:

  • Creates a camera-image subscriber for /image_raw.

  • Creates a PWM-servo publisher for /ros_robot_controller/pwm_servo/set_state.

  • Initializes MediaPipe Hands and its detection and tracking confidence thresholds.

  • Initializes the horizontal and vertical pan-tilt PID controllers.

  • Sets the initial servo positions and gripper state.

  • Initializes the gesture buffer and hand-center tracking variables.

  • Moves all servos to their initial positions.

  • Starts the image-processing thread.

def _set_servos(self, *servos, duration=0.05):
    """servos: triplets of (id, pulse), or pairs of (id, pulse)."""
    msg = SetPWMServoState()
    msg.duration = float(duration)
    for s in servos:
        st = PWMServoState()
        st.id = [int(s[0])]
        st.position = [int(s[1])]
        msg.state.append(st)
    self.pwm_pub.publish(msg)

Servo-control helper that accepts servo IDs and target positions, builds a PWM-servo command, and publishes it. duration sets the movement time.

def image_callback(self, ros_img):
    cv_img = self.bridge.imgmsg_to_cv2(ros_img, 'bgr8')
    if self.image_queue.full():
        self.image_queue.get()
    self.image_queue.put(cv_img)

Camera callback that converts the ROS image message to OpenCV format and stores it in the image queue. If the queue is full, the oldest frame is discarded so that processing uses the latest frame.

main_loop：

python
def main_loop(self):
    while self.running:
        try:
            img = self.image_queue.get(block=True, timeout=1)
        except queue.Empty:
            continue

        self.img_h, self.img_w = img.shape[:2]
        img_rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
        results = self.hands.process(img_rgb)

        hand_found = False
        if results.multi_hand_landmarks:
            for hand_lms in results.multi_hand_landmarks:
                self.mp_draw.draw_landmarks(
                    img, hand_lms, self.mp_hands.HAND_CONNECTIONS)

                # pixel coords
                pixels = [(int(lm.x * self.img_w), int(lm.y * self.img_h))
                          for lm in hand_lms.landmark]

                # palm center (landmarks 0, 2, 9, 17 = wrist + palm edges)
                cx = int((pixels[0][0] + pixels[2][0] + pixels[9][0] + pixels[17][0]) / 4)
                cy = int((pixels[0][1] + pixels[2][1] + pixels[9][1] + pixels[17][1]) / 4)
                self.hand_center = (cx, cy)

                # gesture
                angles = hand_angle(pixels)
                gesture = classify_gesture(angles)
                self.gesture_buf.append(gesture)
                if len(self.gesture_buf) > 5:
                    self.gesture_buf.pop(0)
                # majority vote
                if self.gesture_buf:
                    self.gesture_stable = max(set(self.gesture_buf),
                                              key=self.gesture_buf.count)

                # draw palm center + gesture label
                cv2.circle(img, (cx, cy), 6, (0, 255, 255), -1)
                cv2.putText(img, self.gesture_stable, (cx + 12, cy),
                            cv2.FONT_HERSHEY_SIMPLEX, 0.8, (0, 255, 0), 2)
                hand_found = True
                break  # track first hand only

        if not hand_found:
            self.hand_center = None
            self.gesture_buf.clear()
            self.gesture_stable = 'none'

        # ── pan-tilt PID ──────────────────
        if self.hand_center is not None:
            cx, cy = self.hand_center
            half_w, half_h = self.img_w / 2.0, self.img_h / 2.0

            # yaw (horizontal)
            if abs(cx - half_w) < 15:
                cx = half_w  # dead zone
            self.pid_yaw.SetPoint = half_w
            self.pid_yaw.update(cx)
            self.yaw_pos += int(self.pid_yaw.output)
            self.yaw_pos = max(YAW_MIN, min(YAW_MAX, self.yaw_pos))

            # pitch (vertical)
            if abs(cy - half_h) < 10:
                cy = half_h
            self.pid_pitch.SetPoint = half_h
            self.pid_pitch.update(cy)
            self.pitch_pos -= int(self.pid_pitch.output)
            self.pitch_pos = max(PITCH_MIN, min(PITCH_MAX, self.pitch_pos))
            self.arm_pos += int(self.pid_pitch.output)
            self.arm_pos = max(ARM_MIN, min(ARM_MAX, self.arm_pos))

            self._set_servos([SERVO_YAW, self.yaw_pos],
                             [SERVO_PITCH, self.pitch_pos],
                             [SERVO_ARM, self.arm_pos])

        # ── gripper control ───────────────
        if self.gesture_stable == 'open':
            if self.last_grip != GRIP_CLOSE:
                self.get_logger().info('\033[1;32mGesture: open &rarr; gripper CLOSE\033[0m')
                self._set_servos([SERVO_GRIPPER, GRIP_CLOSE])
                self.last_grip = GRIP_CLOSE
        elif self.gesture_stable == 'close':
            if self.last_grip != GRIP_OPEN:
                self.get_logger().info('\033[1;32mGesture: close &rarr; gripper OPEN\033[0m')
                self._set_servos([SERVO_GRIPPER, GRIP_OPEN])
                self.last_grip = GRIP_OPEN

        cv2.imshow('Arm Hand Control', img)
        key = cv2.waitKey(1) & 0xFF
        if key == 27 or key == ord('q'):
            self.running = False
            break

        self.result_pub.publish(self.bridge.cv2_to_imgmsg(img, 'bgr8'))

    cv2.destroyAllWindows()

The main processing loop performs the following operations:

1. Image acquisition and preprocessing: Gets the latest frame and converts it from BGR to RGB.

2. Hand detection: Runs MediaPipe Hands and draws the hand landmarks and connections.

3. Gesture recognition: Extracts 21 landmark coordinates, calculates finger-bend angles, and applies majority voting to obtain a stable gesture.

4. Pan-tilt tracking: Calculates the hand center by averaging four landmarks at the wrist and palm edges, then uses PID control to move the pan-tilt horizontally and vertically while applying a deadband to prevent jitter.

5. Gripper control: Commands the gripper from the stable gesture. In the current code, open closes the gripper and close opens it.

6. Result display: Draws the hand center and gesture label and displays the processed result.

9.8 Troubleshooting ​

Q1: Gesture recognition fails

Possible causes: The camera image is out of focus, lighting is insufficient, or the hand is outside the detection area.

Solutions:

1. Adjust the camera focus until the image is clear.

2. Provide adequate, even lighting.

3. Keep the hand near the center of the camera frame.

For hand-detection and tracking parameter details, see 9.2.4 Program Overview.

Q2: MediaPipe fails to initialize

Possible causes: The MediaPipe version is incompatible or a required dependency is missing.

Solutions:

1. Confirm that the MediaPipe version is compatible with the system environment.

2. Verify that all required dependencies are installed.

3. Reinstall the MediaPipe package if necessary.

For MediaPipe dependencies and reference resources, see 9.1.3 MediaPipe Workflow and 9.1.4 MediaPipe Learning Resources.

Q3: The fingertip trajectory is not displayed

Possible causes: Gesture confidence is too low, the display window does not have focus, or processing is slow.

Solutions:

1. Confirm that the OpenCV display window opens correctly.

2. Point the camera directly at the hand and maintain a suitable distance.

3. Keep the complete hand within the camera frame.

For the expected fingertip-trajectory behavior, see 9.2.3 Expected Result. For detector and trajectory logic, see 9.2.4 Program Overview.

Q4: Gesture control has excessive latency

Possible causes: Image processing takes too long or system resources are insufficient.

Solutions:

1. Close other resource-intensive applications.

2. If the system is otherwise operating normally, reduce the gesture-control update rate to allow sufficient processing and actuator response time.

For the no-display operating mode used by the hand-following feature, see 9.3.2 Starting and Stopping the Feature.

Q5: Recognition accuracy changes with lighting

Possible causes: Lighting changes affect hand detection or the configured thresholds are unsuitable.

Solutions:

1. Keep the lighting conditions stable.

2. Prevent strong light from shining directly into the camera.

3. Recalibrate the recognition parameters for the actual lighting conditions.
